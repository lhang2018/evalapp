### 关键操作纪律：并行会话在途时如何只提交自己的改动
本次提交时发现 codex 会话有**大量未提交改动**（workboard.json 353 行、README、任务卡、
coding.py、check_collaboration_plan.py 等）。直接 `git add workboard.json` 会把对方的在途工作
扫进我方提交——正是既往事故模式。采用**外科手术式暂存**：

```bash
git show HEAD:<file> > tmp.json        # 取 HEAD 版
# 在 tmp.json 上只做自己的编辑，并用 git diff --no-index 验证差异恰好是自己的几行
blob=$(git hash-object -w tmp.json)
git update-index --cacheinfo 100644,$blob,<file>   # 只改 index，不碰工作区
git add <自己的新文件> && git commit
```

验证三连：`git diff --cached` 只有自己 hunks；`git show HEAD:<file>` 核对关键行在内、
对方改动不在内；`git status` 确认对方改动仍留在工作区。校验器在工作区上跑（render 与在途
workboard 一致）通过。
教训：**"先提交一下"在并行仓库里先查 git status**；Edit 工具写共享文件前也要确认没有他人在途。
