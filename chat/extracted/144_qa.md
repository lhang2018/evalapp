明白。这一点必须成为 EvoAgent 的**顶层架构约束**，而不是普通的功能优先级。

前面讨论主动智能时，容易出现一个方向性偏差：因为主动发现机会很有价值，就不断增加分析、整理、预测和后台活动，最后反而占用资源、增加延迟，甚至影响正在执行的任务。

这绝对不能发生。

**EvoAgent 的核心竞争力，首先是越来越高质量、越来越高效地完成任务。主动智能是在这个基础上增加的价值，不能反过来影响核心能力。**

我建议正式确定以下架构原则。

这里要区分两件事：

- **战略优先级：** 持续优化执行质量和效率，是 EvoAgent 长期发展的首要方向。
- **运行时优先级：** 当前用户正在执行的任务必须得到保护，后台优化不能为了改善未来的系统而损害当前任务。

也就是说，优化核心能力非常重要，但优化实验本身也不能抢占当前任务的关键资源。

特别是主动智能轨道，不能直接修改稳定执行轨道的模型配置、提示词、工具权限或执行计划。

## 三、必须建立运行时保护机制

光在文档中写“互不影响”是不够的，必须通过工程机制保证。

| 保护机制 | 具体要求 |
|---|---|
| 资源配额 | 为稳定执行、后台进化和主动智能分别设置资源预算 |
| 优先级调度 | 关键执行任务优先获得可用的模型调用、CPU、内存和工具并发 |
| 异步分析 | 对话整理、机会发现和可选建议不进入核心执行的同步等待链路 |
| 自动降级 | 资源不足、时延升高或系统异常时，暂停主动智能和非必要实验 |
| 熔断机制 | 发现资源竞争或关键指标退化时，自动停止相关后台任务 |
| 版本隔离 | 候选改进在独立环境测试，不能直接覆盖稳定配置 |
| 发布门禁 | 任何优化都必须证明满足质量、效率、稳定性和安全要求 |
| 一键关闭 | 用户可以关闭主动智能，而不影响核心任务执行能力 |

如果第一版全部运行在用户的 Android 手机上，资源隔离可能无法完全依赖独立硬件。因此，还需要结合独立任务进程、并发限制、任务队列、CPU 与内存控制，以及主动分析的运行时段进行治理。

后续接入个人电脑或 mini Linux 主机后，可以将后台进化和主动分析迁移到独立计算环境，进一步减少对手机端的影响。

但无论部署在哪里，**资源隔离都必须有明确的退化保护，而不能只依靠“希望它不要影响”。**

## 四、优化系统自身也必须接受约束

无限优化最危险的情况，不是优化速度不够快，而是系统为了追求某个指标，反而损害其他能力。

例如：

- 为了提高成功率，无限制增加重试，导致任务变慢、成本暴涨。
- 为了减少延迟，跳过必要的验证，导致错误结果增加。
- 为了改善主动帮助效果，增加后台模型调用，导致核心任务排队。
- 为了提高自动化程度，擅自扩大工具权限。
- 为了快速发布优化，绕过回归测试。

因此，优化目标必须是多维的：

\[
\text{优化目标}
=
\text{执行质量}
+
\text{执行效率}
+
\text{稳定性}
\]

同时受到成本、时延、安全、隐私和资源预算等硬性约束。

不能用一个综合分数掩盖关键退化。例如，执行速度提高了 20%，但正确率明显下降，这不算合格优化。

同样，主动智能即使产生了有价值的建议，只要它导致核心任务超过时延门槛、额外成本超出预算，或者执行质量退化，就必须调整或停止相关主动行为。

## 五、主动智能应该怎样配合核心任务？

举一个完整例子。

用户让 EvoAgent 分析一个代码项目并修复问题。

1. 稳定执行轨道立即分析项目、定位问题、修改代码并运行测试。
2. 后台进化轨道可以在独立资源中研究之前类似失败的案例，但不能抢占当前任务的必要资源。
3. 主动智能轨道可以发现项目还存在一个相关风险，但不应该为了生成额外建议而打断代码修改。
4. 核心任务完成后，如果这项风险确实重要，系统再向用户提供经过核实的补充建议。
5. 如果资源不足，首先暂停主动分析和非必要实验，保障当前任务。
6. 如果后台优化产生了更好的代码分析策略，必须经过独立评测和发布门禁，才能用于后续稳定任务。

这样，主动智能和无限优化是在为核心能力服务，而不是与核心能力争夺资源。

## 六、建议正式冻结的架构决策

我建议将这条原则提升为 EvoAgent 的全局 ADR：

**ADR-1497：核心执行质量优先与多轨运行隔离原则。**

1. 核心任务执行质量、效率和稳定性是最高产品目标。
2. 持续改善核心执行能力是最高优先级的进化方向。
3. 当前用户任务的关键运行资源必须受到保护。
4. 后台进化和主动智能必须具备明确的资源配额、并发限制和降级策略。
5. 主动智能不得成为核心任务执行的强制前置步骤。
6. 主动智能不得擅自修改稳定版本的执行策略、配置和权限。
7. 任何改进均须经过适用的质量、效率、稳定性、安全和成本门禁。
8. 当系统资源不足或核心任务质量受到影响时，主动智能和非必要优化实验必须自动暂停或降级。
9. 用户关闭主动智能后，核心执行和核心进化能力仍应保持可用。
10. 任何新增功能都必须证明其不会让核心任务越过已定义的质量、时延、稳定性和成本门槛。

**最终原则：EvoAgent 可以越来越主动，但绝不能为了主动而牺牲执行；可以无限追求进步，但每次进步都必须服务于更高质量、更高效率、更可靠的任务完成。**
