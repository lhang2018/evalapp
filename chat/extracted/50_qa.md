## ChatGPT

你想到的是 EvoAgent 架构中非常重要的一层：**领域专属技术能力层**。

前面我们讨论了专家、记忆、上下文、Plan、ReAct 和工作流，但这些还不足以让智能体真正成为专业级系统。因为不同领域的高质量执行，往往依赖特定的算法、数据结构、工程工具、验证方法和专业技术。

例如，编程不能只靠提示词和大模型推理，还需要 AST、类型检查、静态分析、测试框架等。AI 漫剧也不能只靠漫剧专家的提示词，还需要角色一致性约束、素材引用、时间轴和音视频处理技术。

**所以，我建议 EvoAgent 在原有架构中正式增加一层：领域技术能力与专业引擎层（Domain Technical Capability Layer）。**

## 二、以编程专家为例：不能只让大模型直接修改代码

假设用户说：“帮我重构这个 Python 项目，提升可维护性，但不要改变现有行为。”

编程专家应该根据任务选择专业技术，而不是始终使用同一套通用 ReAct 流程。

### AST 在这里究竟起什么作用？

AST（抽象语法树）把源代码解析成有结构的节点，而不是只把代码当成普通文本。

例如，将一个函数改名时：

- 纯文本替换可能误改注释、字符串或其他同名标识符。
- AST 或语言服务器可以帮助定位语法节点、符号引用和作用域。
- 修改后再运行解析器、测试和静态分析，验证代码是否仍然有效。

但 AST 也不是万能的。AST 本身不能证明程序行为正确，也不能单独完成所有跨文件、动态类型或复杂语义分析。更可靠的方案是组合 AST、符号解析、LSP、类型检查、测试和运行时验证。

这就是专业技术层的价值：**用确定性工具解决适合确定性工具的问题，让大模型负责理解目标、处理不确定性和选择策略。**

## 三、领域专属技术应该怎样组织？

我不建议把所有技术都写死在专家提示词中，也不建议让模型在每次任务中随意安装和使用任何工具。

应该建立一个统一的**技术能力注册表（Technical Capability Registry）**。

每项能力都应声明：

| 属性 | 示例：Python AST 分析 |
|---|---|
| 能力 ID | `python.ast_analysis` |
| 适用范围 | Python 源代码结构分析 |
| 输入契约 | 文件路径、源码版本、分析目标 |
| 输出契约 | 结构化节点、符号位置、诊断结果 |
| 依赖环境 | 受支持的 Python 版本和解析器 |
| 执行位置 | 本地、服务端或隔离执行环境 |
| 适用条件 | 文件可读取、语法版本受支持 |
| 失败语义 | 语法错误、版本不兼容、超时 |
| 安全策略 | 只读分析，默认不执行目标代码 |
| 验收方式 | 固定测试集、结果一致性和性能测试 |
| 版本信息 | 能力版本、依赖版本和兼容性范围 |

路由器根据任务需求选择专家，专家或规划器再根据任务步骤选择技术能力。两层职责不同：

- **专家路由**回答“谁负责这个任务”。
- **技术能力选择**回答“这个任务需要哪些专业技术”。
- **工作流规划**回答“这些技术以什么顺序、依赖和条件执行”。

例如，编程专家可以在同一任务中依次调用 AST、类型检查和测试工具，也可以让独立分析步骤并行执行。

## 五、技术能力也必须独立进化

这与我们之前确定的 EvoAgent 自进化机制完全一致。

例如，编程专家频繁出现重构后测试失败的问题，系统不能立刻得出“编程专家提示词不好”的结论。

应该先诊断可能原因：

1. 专家选择了错误的重构策略。
2. Planner 漏掉了行为基线。
3. AST 工具没有正确处理目标语法。
4. 代码修改工具产生了错误差异。
5. 测试环境或依赖发生变化。
6. 验收器错误地判断测试结果。

随后针对真正的问题生成候选改进：

- 如果是 AST 解析器版本不兼容，就升级或更换技术组件。
- 如果是规划步骤遗漏，就优化编程专家的规划策略或工作流。
- 如果是工具返回值不可靠，就修复工具适配器。
- 如果是跨项目反复出现的规划问题，再考虑共享内核改进。

每种改进都需要相应的专项评测。例如 AST 技术包应测试语法覆盖、节点定位准确性、修改安全性和运行性能；而编程专家还需要评估端到端任务成功率、行为保持、执行成本和回归影响。

**不能因为某个工具能力提升，就自动认定整个专家也提升了。**

## 六、我建议正式增加三项架构决策

第一，建立统一的领域技术能力层，允许专家按任务动态组合确定性工具、专业算法、外部服务和专用验证器。

第二，所有技术能力都通过统一契约接入 ReAct 和 DAG，声明输入输出、依赖、运行环境、风险、版本和验收方式；禁止专家直接绕过执行器任意调用系统能力。

第三，将技术能力作为独立的进化对象。它们可以单独测试、版本化、灰度发布和回滚，并与专家、工作流、模型配置分别管理。

最后还有一个重要区别：**技术能力包不等于工作流。** AST 是技术能力；“解析项目—分析符号—修改代码—运行测试—验收”才是可能复用的工作流。工作流可以组合多种技术能力，技术能力也可以被多个专家和多个工作流复用。

这样，EvoAgent 就不再只是多个使用不同提示词的智能体，而是一个能够将领域专家、专业技术、执行流程和独立进化机制组合起来的真正智能体平台。
