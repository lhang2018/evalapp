你这个想法非常重要。我认为它会直接决定 EvoAgent 最终是一个“任务执行工具”，还是一个真正有价值的“个人智能体”。

前面我们一直在解决：用户提出任务后，怎样让系统高质量地完成。

你现在提出了更进一步的问题：

**如果用户没有明确提出任务，智能体能不能根据已经授权的上下文，主动发现用户可能需要什么，并在合适的时候提供帮助？即使用户提出了任务，智能体能不能在完成任务之外，进一步发现用户没想到、但确实有价值的事情？**

我的答案是：应该，而且应该把它设计成 EvoAgent 的核心能力之一，而不是以后随手增加的一个功能。

# 二、主动性应该怎么实现？

我建议建立一个新的核心能力：**主动智能与机会发现系统（Proactive Intelligence & Opportunity Discovery，PIOD）**。

它不是一个新的领域专家，也不是另一个独立的聊天机器人，而是横跨通用内核和所有领域专家的共享能力。

它的任务不是无休止地思考，而是持续判断：

- 用户目前正在推进什么？
- 用户已经完成了什么？
- 还有什么事情没有解决？
- 当前有没有值得提供的帮助？
- 现在提供帮助是否合适？
- 这件事值得提醒、建议、准备，还是可以直接执行？

建议形成以下闭环：

# 三、你提到的第一个具体需求：自动整理近期对话，理解用户当前在做什么

我认为这是最值得优先实现的主动智能功能之一。

普通的对话历史，只是把消息按照时间顺序保存下来。

真正的个人智能体应该能够从这些历史中提取持续有用的信息，形成一个可以不断修正的“当前工作状态”。

例如，一个用户最近围绕某个项目讨论了很多次，智能体应该能够整理出：

这与普通的聊天摘要有本质区别。

普通摘要回答的是：“之前说了什么？”

工作状态模型回答的是：“现在正在做什么、进展到哪里、还差什么、下一步做什么最有价值？”

## 这里还需要进一步设计

我建议不要只维护一份越来越长的全局记忆，而是维护分层的状态：

- **会话状态：** 当前这段对话正在解决什么问题。
- **项目状态：** 某个长期项目的目标、决定、进展和待办。
- **近期活动摘要：** 最近一段时间正在处理哪些事情。
- **个人偏好：** 用户明确表达并允许长期保存的工作习惯。
- **待确认推断：** 系统认为可能成立、但尚未得到确认的判断。

这些状态之间需要建立关联，但不能混为一谈。

例如，用户上周研究某项技术，并不代表今天仍然正在研究它。系统应当结合最近活动和明确的任务状态判断，而不是把旧信息当作当前事实。

另外，理解用户当前状况应该主要聚焦于**工作、任务、项目、明确表达的需求和用户授权的上下文**，而不是未经允许地推断用户的私人生活、心理状态或敏感属性。

这是主动智能系统最需要设计好的地方。

我的建议是：

- 默认具备 L1 的上下文理解能力。
- 允许用户开启 L2 的主动建议。
- 对明确授权的任务逐步开放 L3。
- 只有在范围、预算、风险和停止条件明确的情况下，才允许 L4。
- 涉及高影响外部操作时，始终执行适用的授权和确认规则。

用户还应该可以单独设置不同类型任务的自主等级。例如，允许自动整理资料，却要求所有对外发送的消息都先确认。

**自主性不是“什么都不问就执行”，而是在正确的边界内，尽可能减少用户不必要的介入。**

# 六、什么时候主动提供帮助？

主动性还需要一个“时机判断”机制。

建议分成四种触发方式：

| 触发方式 | 示例 | 建议行为 |
|---|---|---|
| 任务完成时 | 用户要求生成一份方案 | 完成主任务后，补充一项高价值遗漏或可选改进 |
| 对话出现阶段性进展时 | 一个长期项目已经明确了目标和关键约束 | 提炼阶段成果，建议最值得推进的下一步 |
| 定期整理时 | 用户开启每日或每周总结 | 整理近期对话、进展、待办和需要关注的问题 |
| 明确事件触发时 | 某个获准跟踪的任务、交付或外部状态发生变化 | 在有意义的变化出现时提醒用户 |

不是每次对话都应该触发主动帮助。

例如，用户只是问“这个词是什么意思”，通常直接回答就足够了。

如果用户正在推进一个复杂项目，已经反复讨论多个阶段，系统就更有理由帮助整理进展、识别遗漏和推荐下一步。

建议建立一个主动帮助价值评估机制：

\[
V = P \times I - C - R - N
\]

其中：

- \(P\)：这项帮助真正有用的可能性；
- \(I\)：潜在价值；
- \(C\)：用户需要承担的注意力和时间成本；
- \(R\)：执行风险；
- \(N\)：重复提醒或不合时宜造成的干扰。

这只是一个概念模型，实际系统还需要考虑任务类型、用户偏好、紧迫程度和授权状态。

它的核心意义是：**发现帮助机会不等于应该打扰用户；只有经过价值与风险判断，才决定是否行动。**

例如，系统发现用户经常接受某类建议，可以把它作为优化线索；但不能直接得出“用户以后都喜欢这类建议”的结论，更不能据此自动扩大操作权限。

# 八、我建议增加一组新的产品级能力

在之前的产品蓝图中，应该正式增加一个一级能力域：

## 主动智能与个人工作状态管理

它至少包含以下功能：

| 功能模块 | 用户可以得到什么 |
|---|---|
| 近期对话自动整理 | 不必自己回顾大量聊天记录 |
| 项目状态汇总 | 知道每个重要项目进展到哪里 |
| 待解决问题识别 | 不容易遗漏尚未完成的关键事项 |
| 下一步行动建议 | 更容易判断当前最值得推进什么 |
| 相关资料发现 | 更快找到已有信息和有价值的外部资料 |
| 任务遗漏检查 | 提前发现方案、报告或流程中的缺口 |
| 超预期结果增强 | 在完成主要任务后获得可选的额外价值 |
| 重复任务发现 | 将反复出现的劳动转化为工作流 |
| 主动提醒与摘要 | 在合适的时间接收有价值的信息 |
| 主动行为控制台 | 管理主动程度、频率、数据范围和授权 |

这里不意味着要一次性全部开发。

第一阶段应该优先实现三个功能：

1. **近期对话与项目状态整理。**
2. **任务完成后的遗漏检查和高价值建议。**
3. **用户可控的主动帮助机制。**

这三项能够直接改善用户体验，而且不需要一开始就构建复杂的后台自主代理网络。

之后再逐步开放定期整理、外部事件监测、主动准备成果和受控自主执行。

## 九、这项设计最终要解决什么问题？

我希望 EvoAgent 最终形成这样的使用体验：

用户说：“帮我完成这项工作。”

EvoAgent 不仅能够高质量完成，而且知道用户为什么要做这件事，能够利用已授权的相关上下文，主动发现重要遗漏，并提供经过判断的额外帮助。

用户没有发出新指令时，它也不只是静静等待。它可以在适当的时候整理近期进展，发现值得关注的问题，或者提前准备下一步工作。

但如果没有真正有价值的事情，它就安静地等待，而不是为了证明自己有自主性而制造活动。

**所以，我们真正要追求的不是一个永远在后台运行、不断做事的智能体，而是一个懂得什么时候应该主动、什么时候应该执行、什么时候应该询问、什么时候应该保持安静的个人智能体。**

这将成为 EvoAgent 区别于单纯聊天工具、传统自动化工具和单纯自进化实验系统的重要产品方向。
