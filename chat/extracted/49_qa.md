## ChatGPT

我的建议是：**上下文压缩能力由全局共享，但压缩策略不能完全全局统一。** EvoAgent 应该采用「共享压缩引擎 + 分层压缩策略 + 专家专属规则 + 全局安全约束」的架构。

因为编程专家、旅游专家、AI 漫剧专家需要保留的信息完全不同。如果所有专家使用相同的压缩方式，就可能出现上下文变短了，但真正重要的信息也被压掉了。

## 一、EvoAgent 的上下文压缩架构


    **全局上下文治理器**
    预算分配、相关性排序、压缩触发、信息完整性检查



    **共享压缩引擎**
    结构化提取、冗余消除、摘要生成、分层压缩、信息恢复索引

        **编程策略**
        错误栈、代码约束、测试结果

    </grid-item>
    <grid-item>


        **旅游策略**
        日期、预算、地点、预订状态

    </grid-item>
    <grid-item>


        **漫剧策略**
        角色设定、分镜、素材引用

    </grid-item>


    **统一安全与完整性校验**
    检查关键约束、未完成任务、工具状态、权限边界和数据来源是否保留


这意味着全局复用的是算法框架、基础组件和治理机制，而不是要求每个专家生成一模一样的摘要。

## 二、哪些应该全局统一，哪些应该独立？

| 能力 | 设计方式 | 原因 |
|---|---|---|
| Token 预算与模型上下文限制 | 全局统一治理，按模型配置 | 防止超出模型容量 |
| 压缩触发和资源控制 | 全局共享 | 统一成本、延迟和安全管理 |
| 冗余消除、结构化提取 | 共享引擎 | 减少重复实现 |
| 通用事实、来源和可信度标记 | 共享数据规范 | 避免压缩后无法判断信息是否可靠 |
| 专家领域信息优先级 | 专家独立配置 | 不同领域的重要信息不同 |
| 任务状态与恢复信息 | 按任务类型定义，执行框架统一 | 保证长任务可以恢复 |
| 压缩质量评测 | 全局评测框架 + 专家专项评测集 | 同时检查通用退化和领域损失 |
| 压缩策略版本 | 全局版本管理，允许专家覆盖 | 方便追踪、灰度和回滚 |

## 三、最关键的是：不能只靠大模型自由总结

例如，编程专家正在修复一个项目，历史上下文非常长。

如果直接让模型总结成一句“修复测试失败”，可能丢失：

- 哪个测试失败、具体错误是什么；
- 已经尝试过哪些方法，哪些无效；
- 修改过哪些文件；
- 哪些操作已经成功；
- 哪些步骤仍未完成；
- 哪些约束不允许违反。

所以我建议采用**结构化状态优先、语义摘要辅助、原始证据可追溯**的三级机制。






      **第一级：不可随意丢弃的结构化状态**
      任务目标、硬性约束、权限状态、当前计划、节点状态、未完成事项和关键工具结果。







      **第二级：可压缩的语义上下文**
      对话摘要、已讨论的方案、重要决策、重复信息和中间推理结论。







      **第三级：可回查的原始证据**
      原始错误栈、工具返回、代码差异、素材文件、历史消息及完整执行日志，按权限保留引用。



压缩时优先去掉冗余，再压缩次要语义信息。需要精确证据时，系统通过引用重新读取原始记录，而不是把所有历史永久塞进提示词。

需要注意，结构化状态也可能写错，所以关键状态应由实际执行结果和独立验证更新，不能只相信模型自己生成的摘要。

## 四、压缩本身也需要进化，但要防止越优化越差

EvoAgent 可以持续优化：

- 什么时候触发压缩；
- 不同信息的保留优先级；
- 摘要长度与细节比例；
- 专家特定的结构化提取规则；
- 如何在需要时恢复原始证据；
- 不同模型下的压缩效果和 Token 成本。

但每次改进都应该评测两组指标：

1. **压缩收益**：Token 减少比例、延迟、调用成本。
2. **信息损失风险**：关键约束遗漏率、事实失真率、任务恢复成功率，以及压缩前后任务质量变化。

不能只因为 Token 减少了 60%，就认为压缩策略更好。如果因此漏掉一个必须遵守的操作约束，这次优化就应判定为失败。

此外，压缩策略针对不同模型也可能不同。同样的上下文长度，在不同模型下的理解能力、信息利用方式和有效窗口并不完全相同，所以应当按「模型配置 × 压缩策略版本 × 专家类型」记录评测结果。

## 五、最终架构决策

我建议正式确定以下原则：

**共享引擎、分层策略、专家定制、模型适配、统一评测、独立回滚。**

- 全局上下文治理器统一控制预算、触发和安全边界。
- 共享压缩引擎提供基础算法与执行接口。
- 各专家声明自己的关键信息、领域优先级和专属压缩规则。
- 每种模型保留经过评测的适配配置。
- 压缩失败时允许回退到更保守的策略，必要时停止执行并提示用户，而不是冒险丢失关键信息。
- 压缩改进必须经过质量、成本和回归评测，不允许某个专家的优化直接覆盖所有专家的配置。

这样，EvoAgent 既不会重复建设多套压缩系统，也不会因为所有专家共用一种压缩策略而失去领域适应能力。
