# EvoAgent 50+ 专项设计目录、来源与缺口台账
**版本：** Register v0.1  
**日期：** 2026-10-21  
**用途：** 追踪 50+ 专项的归并状态，避免遗漏、重复或把摘要误当成完整原稿

## 使用说明

本台账不是声称所有专项全文都已被读取。当前可见历史资料包含少量正式基线文件和若干对话决策摘要。每个主题均标注来源状态：
- **A：基线原文可读取**——已从现有历史文件读取相关内容；
- **B：项目对话摘要支持**——主题与决策在当前项目上下文中可见，但完整专项原稿未能逐段核验；
- **C：待原稿核对/补写**——主题应纳入总设计，但需要找回原稿或重新完成详细设计；
- **D：待决策**——需要用户或后续 ADR 确认。

## 需要补齐的关键材料

1. 找回或重建每个 B/C 项目的原始详细设计正文，不能仅凭目录就宣称完成。
2. 对所有缩写建立正式术语表：中文名、英文名、唯一职责、输入输出、所有者、禁止承担职责。
3. 为每个专项增加统一章节：目标/非目标、边界、依赖、数据契约、状态机、失败处理、安全、评测、V0.1/后续范围。
4. 每个专项至少关联一个端到端场景和验收用例。
5. 所有架构冲突登记为 ADR，记录“旧方案—新方案—原因—影响—迁移路径”。
6. 统一接口 Schema 后，生成 JSON Schema/OpenAPI/事件协议等可供工程使用的文件。
7. 将“设计建议”“已决定”“待验证”“已实现”四种状态分开标注。
