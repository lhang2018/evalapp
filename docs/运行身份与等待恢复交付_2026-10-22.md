## 本次实现

| 链路 | 当前行为与边界 |
|---|---|
| Task / Run | 首次执行和每次恢复分配独立随机 run_id；同任务恢复保存 parent_run_id，失败重跑仍创建新 Task，并关联父 Task / Run。SQLite 事务比较旧状态和旧 run_id，拒绝重复领取或过期请求。 |
| 历史与事件 | 运行开始即写入记录，结束补齐结果；恢复不再覆盖上一轮。控制器、ReAct、DAG 节点事件和诊断关联实际 run_id，回放保留运行身份。外部副作用去重继续使用逻辑 task_id。 |
| 用户澄清 | 分类歧义和 ReAct request_user 进入 WAITING_USER，持久化问题 ID、阶段和问题正文，不转成验收失败。答案绑定具体问题，原子消费；重复相同答案不产生第二次运行，不同答案或过期问题被拒绝。 |
| ReAct 续跑 | 检查点保存消息、行动/工具结果、计划进度、循环防护计数、已投递答案和下一轮位置。恢复沿用累计预算，并将已有工具结果纳入最终独立验收，避免因证据丢失而重复调用。 |
| 工作流暂停 | 支持在 DAG 批次边界暂停；已启动的批次完成后保存输出。恢复跳过已完成节点，任务预算与工作流作用域预算均累计。 |
| 运行清单 | 选定实际专家、模型和工作流后冻结清单，使用 Expert.version 和真实路由模型。尚未选定的引用保留 null；冻结后拒绝覆盖。恢复时检查专家、模型和工作流版本引用。 |
| 旧库 | Schema v2 追加 task_runs.parent_run_id；旧运行记录保留，新 Task 字段有兼容默认值。 |
| 客户端 | 本地持久化服务端状态、运行 ID 和待答问题；任务卡提供“回答并继续”。API 客户端发送问题 ID 与答案。CLI 提供 answer 命令。 |

## 使用与验证

- `GET /tasks/{task_id}`：读取 waiting_request 和 current_run_id。
- `POST /tasks/{task_id}/answer`：正文为 `{"request_id":"question_…","answer":"补充信息"}`。新答案返回 202；同答案重试返回 200；输入格式错误 400，任务不存在 404，状态或答案冲突 409。202 表示已接受并安排执行，后续状态以任务查询为准。
- `GET /tasks/{task_id}/runs`：按时间读取运行历史和父运行关系。
- `python -m evoagent.cli answer <task_id> <request_id> "补充信息"`：持久化答案并同步续跑。
- 现有 pause / resume 接口继续适用；未决副作用仍须对账，force 不允许绕过工具网关的未知结果保护。

新增 [17 项服务端回归](E:/evalapp/tests/test_run_continuation.py)，覆盖澄清前后工具不重复、证据与预算保留、相同答案重试、非法/冲突答案、跨连接原子消费和运行领取、应用重启、分类阶段继续规划、组件版本改变、旧库迁移、工作流暂停重启，以及 HTTP 鉴权和状态码。新增 2 项客户端回归覆盖问题持久化与回答请求。

## 下一步与关闭条件

ALN-04 仍为实现中，后续按以下顺序完成：

1. **异步审批与恢复联动**：批准/拒绝后准确消费原审批并继续对应等待节点，保留审批授权范围和审计关联。当前已有审批记录与恢复门禁，不等于完整异步链路已闭合。
2. **运行中强杀后的接管**：增加持久运行所有权、租约/失联判据和显式中断恢复事务；先结束旧运行，再根据检查点和副作用账本开启子运行。当前已验证“持久化暂停/等待后，关闭并重新创建 App 再恢复”，未宣称覆盖 RUNNING 中途强杀；没有自动扫描和接管孤儿运行。
3. **剩余契约与验收**：补节点取消传播、任意指定检查点恢复、工具/环境兼容检查和实际制品版本固定；验证审批、强杀、外部回执对账及真机界面的组合路径。

若答案已持久化、进程在启动续跑前退出，任务保留为 SUSPENDED，可通过现有 resume 入口恢复；相同答案重试本身不会重复启动运行。跨进程重复执行受运行领取事务约束，但不能把这一点等同于完整分布式调度或进程故障恢复。
