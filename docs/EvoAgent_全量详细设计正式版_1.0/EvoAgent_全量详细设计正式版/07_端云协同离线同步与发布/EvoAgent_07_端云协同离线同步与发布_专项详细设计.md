# EvoAgent 专项详细设计｜07_端云协同离线同步与发布
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### O-01｜本地事件持久化与容量治理

**设计目标与范围**  
关键事件、版本清单和同步状态本地可靠保存。

**正式设计决策**  
关键事件先落盘；存储不足不得静默删除未同步关键事件。

**输入与输出契约**  
输入：本地事件、同步批次、Runtime Manifest、制品清单、设备状态和隐私策略。输出：回执、诊断包、对账结果、发布制品和客户端回滚记录。

**标准处理流程**  
本地落盘 → 隐私过滤 → 批次上传/版本对账 → 持久化确认 → 诊断/评测/发布 → 客户端校验激活 → 反馈与回滚。

**控制权与边界**  
同步服务与版本分发服务各自管理协议状态；上传成功不等于批准发布。

**异常与恢复**  
断网保留队列；重复批次幂等；部分成功精确补传；未知版本隔离；同步与更新互不阻塞。

**安全与架构不变量**  
状态必须可追溯和可恢复；未知副作用不得盲目重放；历史版本与证据不可被新版本覆盖。

**验收标准**  
验收目标：关键事件、版本清单和同步状态本地可靠保存。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。

验收目标：维护设备版本、目标发布、激活状态和应用回执。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
