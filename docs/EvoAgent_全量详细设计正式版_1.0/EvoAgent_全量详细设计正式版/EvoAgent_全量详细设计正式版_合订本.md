# EvoAgent 全量总体架构与 PRD 正式版
**正式设计基线 1.0｜2026-10-20**

## 1. 产品定义
EvoAgent 是 Android 手机优先、本地优先的个人通用智能体系统。用户通过文字/语音提出目标；系统解析意图、约束与风险，选择领域专家和执行路径，优先复用稳定工作流，必要时进行受限动态规划；工具动作经过统一权限、预算、Schema 和副作用控制；结果经过独立验收，运行证据用于诊断、候选改进、独立评测、受控发布和回滚。

“无限进化”在工程上指持续、可验证且有预算的改进循环，不代表无限权限或无边界自修改。成功标准是长期提升真实任务成功率、质量、恢复率和资源效率。

## 2. 正式架构决策
1. Android 手机是第一正式终端；Windows、平板和其他桌面设备为后续扩展，不是首发前置依赖。
2. 端侧与运行宿主解耦。Android 负责交互、审批、原生设备桥接、本地日志、离线能力、更新校验和诊断导出。
3. 复杂模型路由、长任务、全局记忆治理、进化评测与发布可由远端服务或用户自有宿主承担；远端不是关键状态持久化的唯一位置。
4. 采用受保护共享内核与独立领域专家。专家拥有私有工具、技能、工作流、记忆、提示策略和评测，但不得覆盖全局安全、权限、Task of Record 或发布门禁。
5. 稳定执行轨道与候选进化轨道隔离。候选必须通过独立评测和发布控制器，不能自我批准。
6. Task of Record 是单次任务权威事实源；Goal、Task、Node、Sync、Asset、Approval 和 Release 使用独立状态机。
7. 模型只提出动作，所有外部副作用经过 Tool Gateway/Action Guard。
8. 事件、检查点和副作用账本分离：日志用于追溯，检查点用于恢复，副作用账本用于对账和防重复。
9. 上下文压缩引擎可共享，但记忆命名空间、隐私、保留和领域策略隔离。
10. 进化必须证明真实收益；一次成功只形成候选，不自动晋升稳定能力。

## 3. 总体逻辑架构
```text
Android Phone (first-class client)
  ├─ Interaction / Voice / Approval UI
  ├─ Local Task State / Event Store / Checkpoints
  ├─ Native Device Bridge / Action Guard
  ├─ Offline Capability Runtime
  ├─ Sync Coordinator / Release Verifier / Rollback
  └─ Diagnostics Export
          │ authenticated versioned protocol
          ▼
EvoAgent Host / Backend (optional personal host or remote service)
  ├─ Unified API / Identity / Policy Gate
  ├─ Task Orchestrator + Intent Router + Planner
  ├─ Workflow/DAG Runtime + Agent Runtime Adapter
  ├─ Model Gateway + Tool/Capability Gateway
  ├─ Memory & Context Governance
  ├─ Event/Trace + Recovery Coordination
  ├─ Diagnostics + Evolution Controller
  ├─ Independent Evaluation/QEEG
  └─ Promotion/Release/Distribution Controller
```

## 4. 八个逻辑服务
- **SV-01 任务编排：** Task/Run/Node 状态、路由、Planning、ReAct、DAG、取消和恢复。
- **SV-02 模型网关：** 供应商适配、模型选择、请求格式、超时/限流和成本对账。
- **SV-03 能力与工具：** Tool/Skill/Workflow/Expert/Capability Pack 注册、契约和依赖。
- **SV-04 记忆与上下文：** 命名空间、检索、冲突、ContextManifest、压缩和来源追踪。
- **SV-05 同步与观测：** 事件接收、幂等同步、版本关联、健康/回滚反馈。
- **SV-06 进化与诊断：** 问题案例、根因假设、候选提案和实验预算。
- **SV-07 评测与发布门禁：** 独立质量、安全、兼容和成本评测。
- **SV-08 版本分发：** 策略/工作流/能力包/模型档案/客户端制品的签名分发、灰度和回滚。

八个逻辑服务不意味着必须拆成八个微服务。个人部署优先模块化单体，只有负载、故障隔离或安全边界有证据时才拆分。

## 5. 四个受保护控制器
- **CTRL-01 Runtime Controller：** 执行状态、工具授权、预算、取消和恢复。
- **CTRL-02 Evolution Controller：** 候选实验、诊断队列、实验预算与停止条件；不拥有最终发布权。
- **CTRL-03 Evaluation Gate Controller：** 独立质量/安全/兼容性判定；候选不能修改门槛。
- **CTRL-04 Release Controller：** 正式版本指针、分发、灰度、晋级、暂停和回滚。

## 6. 任务执行模式
- 稳定工作流：适合重复且可验收任务，先检查输入、权限、依赖、版本和预算。
- 混合 Agent 工作流：主流程确定，局部节点需要动态判断。
- 动态规划：没有适用工作流时，在工具白名单、最大步数、时限、预算和停止条件内探索。

Router 决定候选路径；Planner 生成计划；DAG Runtime 管节点状态；ReAct 只做受约束局部循环；Action Guard 拥有动作允许/拒绝的最终策略权；Evaluator 独立验收。

## 7. 产品功能全景
- 自然语言/语音目标输入、必要问题澄清、任务历史、取消、审批、结果与部分完成展示。
- 多层意图路由、领域专家、模型档案和工具契约。
- 稳定工作流复用、轨迹到候选工作流编译、依赖图和资产生命周期。
- 用户/项目/领域/会话/任务分层记忆，动态上下文、压缩、可信度与来源追踪。
- 运行事件、故障分类、工具健康、独立诊断、QEEG 评测和回归案例库。
- AGIG 长期目标治理、主动机会评估、APRO 资源调度、预算和停止控制。
- Android 受控设备操作、本地事件队列、离线诊断包、可靠同步、版本校验和回滚。
- 端云协同进化、隔离实验、独立门禁、签名发布、灰度和线上收益反馈。

## 8. 版本与可复现
每次运行固定绑定不可变 Runtime Manifest，至少记录 App/Core、Runtime Adapter、模型档案、Router/Planner、Context Policy、专家、工作流、工具适配器、评测集和环境摘要。运行中默认不热切换组件版本；升级需明确恢复/迁移策略。

## 9. 产品非目标与硬边界
- 不允许模型直接执行未注册工具。
- 不允许候选修改权限、安全规则、评测门槛或稳定版本指针。
- 不允许将一次成功轨迹直接作为稳定工作流。
- 不允许未经授权上传原始对话、截图或敏感文件。
- 不允许在副作用状态未知时盲目重放。
- 不允许主动目标无限递归或超预算运行。
- 不允许将 Mock 结果声明为真实供应商能力。

## 10. 验收总原则
任务成功必须由产物、结构、语义质量、外部状态或用户确认等证据证明；“模型说完成”不是充分证据。每个正式能力均需版本、依赖、权限、评测、适用范围和回滚信息。


# EvoAgent 全量详细设计正式版｜总目录与追踪矩阵

## 阅读顺序
总体架构/PRD → 任务执行内核 → 记忆上下文 → 专家能力与工作流 → 观测诊断评测与进化 → 自主目标与资源治理 → 产品部署/端侧 → 端云同步发布 → 安全工程化 → 数据契约与验收。

## P｜产品与部署
- **P-01｜产品定位与价值主张**：个人通用智能体；真实任务完成、可靠复用和可验证改进。
- **P-02｜全量 PRD 与产品边界**：用户场景、功能需求、非目标、权限、任务生命周期和验收口径。
- **P-03｜Android 手机优先战略**：Android 手机第一正式终端，承载交互、审批、设备能力和运行证据。
- **P-04｜Windows 桌面端扩展路线**：后续增强开发、长任务和桌面工具能力，不作为 Android 首发依赖。
- **P-05｜Mini PC/Linux 个人宿主**：个人电脑或微型 Linux 主机提供常驻服务、文件处理和本地工具。
- **P-06｜多端交互与运行宿主解耦**：Android、未来桌面端、CLI/API 与执行宿主分离。
- **P-07｜本地优先与可选远程服务**：断网保留本地任务状态、事件、可用能力和导出。
- **P-08｜DeepSeek Harness 适配策略**：Harness 作为可替换 Agent Runtime，而非产品架构本身。

## R｜任务执行内核
- **R-01｜统一任务入口与 Task of Record**：统一接收目标、约束、预算、授权和验收条件。
- **R-02｜意图理解与多层路由**：识别领域、复杂度、风险、工具需求和不确定性。
- **R-03｜路由质量评测与纠错**：评估专家选择、工作流匹配、执行模式和模型选择。
- **R-04｜Planner 与计划修订**：目标拆解、依赖、验收和恢复策略。
- **R-05｜ReAct 执行循环**：观察、动作提议、授权检查、执行、再观察和停止。
- **R-06｜DAG/工作流运行时**：节点依赖、条件、并发、重试、审批、检查点和补偿。
- **R-07｜固定流程、混合 Agent 与动态规划选择**：决定采用稳定 DAG、局部 Agent 节点或动态规划。
- **R-08｜工具注册表与能力契约**：工具 Schema、权限、风险、超时、幂等、成本和健康检查。
- **R-09｜Action Guard 与动作授权**：执行前检查工具权限、目标范围、风险、预算和用户授权。
- **R-10｜取消、暂停、等待与人工接管**：任务控制、审批等待、补充信息和人工接管。
- **R-11｜检查点与恢复管理**：保存 DAG 节点状态、恢复游标和必要输入输出引用。
- **R-12｜外部副作用账本**：跟踪外部操作意图、提交、确认、失败和对账状态。

## M｜记忆上下文
- **M-01｜用户长期记忆**：稳定偏好、长期约束和可复用授权偏好。
- **M-02｜项目记忆**：项目决策、当前状态、技术约束、里程碑和未决事项。
- **M-03｜领域记忆命名空间**：旅游、编程、漫剧、手机操作等专家的领域经验隔离。
- **M-04｜会话上下文管理**：当前对话近期信息、指代、未解决问题和交互状态。
- **M-05｜任务工作记忆**：当前任务计划、观察、证据、中间结果和未决步骤。
- **M-06｜上下文压缩与预算管理**：窗口限制下保留目标、约束、决策、验收、未决项和来源。
- **M-07｜上下文来源追踪与可信度**：追踪来源、摘要引用、时间、版本和可信状态。
- **M-08｜记忆冲突与事实更新**：处理新旧偏好、项目决策、外部事实和推断冲突。

## C｜专家能力与工作流

- **C-05｜Capability Pack 能力包**：按业务目标打包工具、技能、工作流、评测和依赖。

- **C-14｜Android 受控手机操作能力包**：受控观察、动作、权限检查和真实状态验证。

## E｜观测诊断评测与进化
- **E-01｜运行事件与 Trace**：记录 task/run/node/tool/model/asset 版本、成本、时延和结果。
- **E-02｜统一故障分类与证据等级**：区分规划、模型、工具、供应商、网络、权限、预算和验收故障。
- **E-03｜诊断与执行解耦**：分析根因并提出改进，不在生产路径直接修改。
- **E-04｜工具健康与 Agent 能力分离**：分开评估工具可用性和智能体任务能力。
- **E-05｜QEEG 质量工程与评测治理**：独立验证任务质量、成功率、成本、时延、安全和兼容。
- **E-06｜评测集版本、覆盖与防泄漏**：管理测试样本、标签、来源、难度、覆盖和保密。
- **E-07｜进化候选生成**：从失败、成本异常、质量退化和能力缺口提出改进。
- **E-08｜隔离实验环境**：隔离候选代码、配置、数据、凭证、网络和资源。
- **E-09｜发布晋级门禁**：决定候选是否可发布、灰度、晋级或拒绝。
- **E-10｜稳定轨道与候选轨道隔离**：生产任务绑定稳定资产，实验在候选轨道执行。
- **E-11｜进化收益与退化评估**：测量改进对质量、效率、恢复和稳定性的实际影响。
- **E-12｜失败案例转回归资产**：把真实失败转成可复现测试。
- **E-13｜独立进化控制器**：管理诊断队列、候选计划、实验预算、并发和停止条件。

## G｜自主目标与资源治理
- **G-01｜长期目标注册表**：保存用户目标、维护目标、派生子目标和主动机会。
- **G-02｜主动机会发现**：从运行证据、质量退化和用户目标发现机会。
- **G-03｜目标价值评估与排序**：比较收益、证据、成本、风险、时效和机会成本。
- **G-04｜自主等级与授权矩阵**：建议、准备、沙箱、授权内执行和长期推进的权限分层。
- **G-05｜Goal 状态机**：管理目标提出、运行、等待、暂停、阻塞、完成和过期。
- **G-06｜无进展检测与停止控制器**：识别循环、重复失败、收益递减、预算耗尽和目标失效。
- **G-07｜递归子目标治理**：管理拆分深度、数量、循环依赖和重复子目标。
- **G-08｜前台/后台资源调度**：协调交互任务、长任务、同步、评测和进化实验。
- **G-09｜预算账本与费用控制**：管理模型 token、外部 API、生成服务、CPU/磁盘和并发预算。
- **G-10｜主动任务结果归因**：比较预期收益与实际收益，决定继续、暂停或终止。

## O｜端云协同与可靠性
- **O-01｜本地事件持久化与容量治理**：关键事件、版本清单和同步状态本地可靠保存。
- **O-02｜可靠同步与幂等回执**：断点续传、稳定事件 ID、批次 ID、部分成功回执和退避。
- **O-03｜离线诊断包导出**：按任务、时间、能力和失败状态导出结构化证据。
- **O-04｜诊断包受控导入**：校验外部包、隔离数据并进入诊断流程。
- **O-05｜Runtime Manifest 运行版本清单**：记录每次任务实际使用的组件版本组合。
- **O-06｜端云协同进化闭环**：证据上行、诊断、候选评测、发布下行和线上反馈。
- **O-07｜版本分发、激活与回滚**：分发策略、工作流、模型档案、能力包和客户端制品。
- **O-08｜离线降级与恢复**：服务端、模型、网络或同步不可用时保留允许的本地能力。
- **O-09｜附件与大型资产存储**：管理图片、音频、视频、代码产物和诊断附件。
- **O-10｜多设备状态一致性**：维护设备版本、目标发布、激活状态和应用回执。

## S｜安全与工程化
- **S-01｜安全策略与最小权限**：统一工具权限、数据范围、风险等级、审批和拒绝规则。
- **S-02｜隐私与敏感数据治理**：最小化采集、脱敏、访问控制、保留和删除。
- **S-03｜模型输出与外部内容不可信边界**：防止提示注入、恶意工具参数和导入指令。
- **S-04｜本地沙箱与执行隔离**：隔离候选代码、文件系统、进程、网络和资源。
- **S-05｜审计日志与决策可解释性**：记录授权、执行、诊断、评测、发布、回滚和审批。

### S-01｜安全策略与最小权限

**设计目标与范围**  
统一工具权限、数据范围、风险等级、审批和拒绝规则。

**正式设计决策**  
策略不确定时 fail closed；专家和候选不能放宽全局权限规则。

**输入与输出契约**  
输入：策略版本、身份/授权、工具请求、运行环境、秘密引用和审计事件。输出：允许/拒绝决策、隔离执行结果、审计记录和恢复状态。

**标准处理流程**  
身份与范围校验 → 风险/策略判定 → 最小权限执行 → 记录审计 → 校验结果 → 复核/恢复。

**控制权与边界**

## 阶段 D：观测、诊断与独立评测
交付统一事件协议、故障分类、工具健康、诊断案例、QEEG 评测套件、隐藏回归集、失败案例库和成本/质量指标。
验收：能区分模型/工具/网络/权限/验收问题；诊断只能产生候选，不能直接修改生产。

## 阶段 E：主动目标与资源治理
交付 AGIG Goal Registry、机会候选、价值排序、自主等级、无进展停止、APRO 资源调度、预算账本和结果复盘。
验收：目标循环可停止；子目标不能扩大授权；预算耗尽时不再发起新调用。

## 阶段 F：Android 首发端与离线可靠性
交付 Android 交互/审批、受控原生桥接、本地事件队列、检查点、离线导出、同步回执、版本校验和回滚。
验收：断网、进程杀死、设备重启、权限撤销、更新损坏、签名失败和恢复联网测试通过。

## 阶段 G：端云进化闭环与受控发布
交付同步与观测服务、诊断/实验、独立门禁、Release Manifest、能力包分发、灰度、健康观察和回滚。
验收：从线上失败到候选、评测、发布、客户端应用和线上收益反馈可完整追踪。

## 阶段 H：领域能力包与跨端扩展
交付编程专家（AST/LSP/测试）、AI 漫剧能力包、手机操作能力包；后续接入 Windows/平板/CLI。
验收：每个能力包有依赖、权限、成本、质量验收和版本回滚；跨端复用同一协议。

## 系统级验收用例
1. 重复创建请求不会重复创建逻辑任务。
2. 高风险动作未审批时不会执行。
3. 工具 Schema 错误被阻断并产生可定位事件。
4. 超时后副作用未知时先对账，不盲重试。
5. 进程重启后任务状态和检查点一致。
6. 取消后不会继续创建新动作。
7. 预算耗尽后停止新的模型/工具调用。
8. 工具成功但产物不满足验收时任务不标记成功。
9. 历史运行可通过 Runtime Manifest 还原组件版本。
10. 断网时事件可靠落地并可导出。
11. 重复同步在服务端幂等。
12. 恶意诊断包被拒绝或隔离。
13. 候选评测失败不会改变稳定指针。
14. 更新签名/兼容性验证失败不会激活。
15. 客户端更新后健康检查失败能回滚。
16. 领域专家改动触发依赖图确定的回归范围，核心安全集始终执行。
17. 路由低置信时澄清或安全回退。
18. 压缩后硬约束和验收标准仍保留。
19. 主动目标达到无进展阈值后停止。
20. 晋级报告包含基线、样本量、质量/成本/安全和兼容性证据。


# EvoAgent 架构决策记录（ADR）正式台账

## ADR-001：Android 手机作为第一正式终端
**状态：已确认。** Android 是首发交互端；Windows、平板等为后续扩展。端侧保留交互、授权、设备桥接、离线事件和更新验证能力。

## ADR-002：本地优先，远程能力可选
**状态：已确认。** 任务状态、关键事件、检查点和副作用账本必须有可靠持久化；远端不可用时降级但不丢证据。

## ADR-003：受保护共享内核 + 独立领域专家
**状态：已确认。** 专家独立演进提示词、工具、技能、工作流、记忆和评测；核心安全、权限、Task of Record 和发布门禁受保护。

## ADR-004：工作流优先，动态规划受限
**状态：已确认。** 先匹配已验证工作流；主流程稳定但局部需要推理时采用混合 Agent；无适用流程才动态规划。

## ADR-005：工具调用统一经过 Action Guard
**状态：已确认。** 模型输出只是动作提议；工具 Schema、权限、风险、预算、幂等和状态检查必须在唯一执行边界完成。

## ADR-006：事件、检查点与副作用账本分离
**状态：已确认。** 事件记录事实，检查点保存恢复状态，副作用账本用于外部状态对账和防重复。

## ADR-007：稳定轨道与进化轨道隔离
**状态：已确认。** 候选不直接影响稳定任务；评测门禁和发布控制器独立；历史版本不可变、可回滚。

## ADR-008：共享压缩引擎 + 领域上下文策略
**状态：已确认。** 算法、预算和评测框架共享；记忆命名空间、权限、领域策略和保留周期隔离。

## ADR-009：八个逻辑服务不等于八个微服务
**状态：已确认。** 先以模块化单体实现清晰逻辑边界；根据负载、安全和故障隔离证据再拆分物理部署。

## ADR-010：DeepSeek Harness 作为可替换 Runtime 候选
**状态：方向已确认；具体能力需 PoC。** 业务层依赖 AgentRuntimeAdapter；DSH API、插件生命周期、取消/恢复和沙箱能力在固定 commit 验证。

## ADR-011：候选不拥有安全规则、评测门槛和发布指针
**状态：已确认。** 这些属于受保护控制面，不可由自进化候选修改或自我批准。

## ADR-012：任务运行绑定不可变 Runtime Manifest
**状态：已确认。** 运行期间固定组件版本；升级需明确恢复/迁移策略，不自动热切换。

## ADR-013：主动机会不等于授权任务
**状态：已确认。** 机会发现仅创建候选；通过价值、证据、授权、预算和停止条件检查后才能启动任务。

## ADR-014：稳定主题 ID 作为正式索引
**状态：已确认。** 历史部分专项编号无法从归档完整恢复；使用 P/R/M/C/E/G/O/S 等稳定 ID，保留可恢复的 CLEK、ACMO、ARCBG、APRO、QEEG、KCLG、AGIG 名称，不虚构其他历史编号。


# EvoAgent 术语表与状态约定

| 术语 | 定义 |
|---|---|
| Task of Record | 单次逻辑任务的唯一权威记录 |
| Goal | 长期目标、维护目标或主动机会；与一次 Task 分离 |
| Run | 一次具体执行过程或恢复尝试 |
| Node Run | DAG 节点的一次执行实例 |
| ReAct | 受约束的观察—动作—再观察局部循环 |
| Planner | 将目标转换为计划，不拥有动作授权权 |
| DAG Runtime | 管理依赖、节点状态、分支、重试、检查点和恢复 |
| Tool | 有 Schema、权限、幂等和错误契约的原子操作 |
| Skill | 可复用的知识/策略/操作规则 |
| Workflow | 有输入输出契约、依赖、分支、审批和验收的可执行流程 |
| Expert | 领域能力组合，拥有领域资产和评测但受共享内核约束 |
| Capability Pack | 可安装、可验证、可升级和回滚的业务能力包 |
| Harness | 驱动局部模型循环、工具调用和上下文的运行机制 |
| Runtime Manifest | 固定一次运行实际使用的组件版本组合 |
| Event/Trace | 记录发生了什么的证据 |
| Checkpoint | 保存任务恢复所需状态的快照/游标 |
| Side-effect Ledger | 记录外部副作用意图、提交、确认和对账状态 |
| QEEG | 质量工程与评测治理 |
| KCLG | 知识资产、技能生命周期与能力复用治理 |
| AGIG | 自主目标与主动性治理 |
| APRO | 自适应性能、资源调度与成本优化 |
| CLEK | 经验分层、用户习惯与领域知识隔离和晋升治理 |
| ACMO | 自适应上下文管理与优化：检索、压缩、ContextManifest、可信度和缓存 |
| ARCBG | 自适应推理深度与能力/预算治理 |
| Runtime Controller | 运行时受保护控制器 |
| Evolution Controller | 进化实验编排控制器 |
| Evaluation Gate Controller | 独立评测门禁控制器 |
| Release Controller | 正式版本发布、分发、晋级和回滚控制器 |

## 状态约定
- 正式设计：模块职责、状态边界、数据契约、安全门禁和验收原则。
- 需 PoC 验证：依赖第三方 Runtime、模型 API、设备桥接或供应商行为的部分。
- 运行时配置：用户预算、工具许可、数据保留、模型供应商和宿主位置。
- 文档设计不等于代码已实现；实现状态以工程和自动化测试为准。
