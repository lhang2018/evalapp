# EvoAgent 专项详细设计｜04_观测诊断评测与进化
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### E-01｜运行事件与 Trace

**设计目标与范围**  
记录 task/run/node/tool/model/asset 版本、成本、时延和结果。

**正式设计决策**  
诊断、评测和发布职责分离；证据不足时保持未知或候选状态，不自动改变稳定资产。

**输入与输出契约**  
输入：结构化事件、Runtime Manifest、评测集版本、稳定基线、候选差异和资源预算。输出：故障分类、根因假设、候选提案、评测报告和发布决策证据。

**标准处理流程**  
采集证据 → 分类故障域 → 提出可反驳假设 → 构造隔离候选 → 运行评测 → 比较基线 → 门禁决策 → 线上观察。

**控制权与边界**  
诊断器负责假设，QEEG 负责独立质量判断，Release Controller 负责发布。

**异常与恢复**  
证据不足标记 unknown；环境不一致、样本不足或数据污染时评测无效，不得晋级。

**安全与架构不变量**  
关键结果必须有来源、版本和验收证据；无法证明时明确标注未知，不把假设写成事实。

**验收标准**  
验收目标：记录 task/run/node/tool/model/asset 版本、成本、时延和结果。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
