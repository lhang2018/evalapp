# EvoAgent 专项详细设计｜05_自主目标与资源治理
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### G-01｜长期目标注册表

**设计目标与范围**  
保存用户目标、维护目标、派生子目标和主动机会。

**正式设计决策**  
Goal 表示长期目的，Task 表示一次执行；两者通过引用关联而不共享万能状态字段。

**输入与输出契约**  
输入：目标来源、成功条件、授权、预算、期限、父目标、运行证据和资源压力。输出：Goal 状态、机会候选、优先级、预算分配和停止/复盘记录。

**标准处理流程**  
注册目标 → 价值/风险评估 → 授权检查 → 排序与资源预留 → 创建任务 → 监控成本/进展 → 停止或复盘。

**控制权与边界**  
AGIG 管目标，APRO 管资源，Runtime 执行；用户可以撤销授权。

**异常与恢复**  
无进展、预算耗尽、授权失效或目标过期时暂停/终止；不能通过递归生成子目标规避停止。

**安全与架构不变量**  
关键结果必须有来源、版本和验收证据；无法证明时明确标注未知，不把假设写成事实。

**验收标准**  
验收目标：保存用户目标、维护目标、派生子目标和主动机会。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。

本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
