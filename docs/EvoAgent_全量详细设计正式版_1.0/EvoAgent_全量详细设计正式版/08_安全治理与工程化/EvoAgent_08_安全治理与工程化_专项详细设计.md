# EvoAgent 专项详细设计｜08_安全治理与工程化
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### S-01｜安全策略与最小权限

**设计目标与范围**  
统一工具权限、数据范围、风险等级、审批和拒绝规则。

**正式设计决策**  
策略不确定时 fail closed；专家和候选不能放宽全局权限规则。

**输入与输出契约**  
输入：策略版本、身份/授权、工具请求、运行环境、秘密引用和审计事件。输出：允许/拒绝决策、隔离执行结果、审计记录和恢复状态。

**标准处理流程**  
身份与范围校验 → 风险/策略判定 → 最小权限执行 → 记录审计 → 校验结果 → 复核/恢复。

**控制权与边界**  
TSEG/Policy Gate 和受保护控制器；候选不能修改安全规则、秘密和审计记录。

**异常与恢复**  
安全策略、密钥或数据状态未知时 fail closed；迁移/恢复失败时保留原数据并停止写入。

**安全与架构不变量**  
权限、隐私、预算和授权边界优先于任务完成率；策略不确定时拒绝或请求确认。

**验收标准**  
验收目标：统一工具权限、数据范围、风险等级、审批和拒绝规则。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
