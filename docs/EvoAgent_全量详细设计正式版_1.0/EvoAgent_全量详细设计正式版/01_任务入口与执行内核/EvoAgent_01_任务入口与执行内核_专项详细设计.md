# EvoAgent 专项详细设计｜01_任务入口与执行内核
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### R-01｜统一任务入口与 Task of Record

**设计目标与范围**  
统一接收目标、约束、预算、授权和验收条件。

**正式设计决策**  
Task of Record 是单次任务唯一权威事实源；重复创建通过幂等键处理。

**输入与输出契约**  
输入：Task、约束、授权引用、预算、Runtime Manifest、当前状态和能力清单。输出：计划/动作提议、节点状态、工具结果引用、验收结果和事件。

**标准处理流程**  
解析目标 → 检查风险与授权 → 选择执行路径 → 执行单步/节点 → 验证观察 → 更新状态/检查点 → 交付或安全停止。

**控制权与边界**  
Runtime Controller 拥有最终执行状态；Planner 与模型只提交计划/动作提议。

**异常与恢复**  
按参数、权限、网络、模型、工具、验收或未知副作用分类；仅对幂等或可证明安全的动作重试。

**安全与架构不变量**  
关键结果必须有来源、版本和验收证据；无法证明时明确标注未知，不把假设写成事实。

**验收标准**  
验收目标：统一接收目标、约束、预算、授权和验收条件。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。

### R-11｜检查点与恢复管理

**设计目标与范围**  
保存 DAG 节点状态、恢复游标和必要输入输出引用。

**正式设计决策**  
检查点保存恢复状态，不替代事件日志；恢复前重新核验外部状态和授权。

**输入与输出契约**  
输入：Task、约束、授权引用、预算、Runtime Manifest、当前状态和能力清单。输出：计划/动作提议、节点状态、工具结果引用、验收结果和事件。

**标准处理流程**  
解析目标 → 检查风险与授权 → 选择执行路径 → 执行单步/节点 → 验证观察 → 更新状态/检查点 → 交付或安全停止。

**控制权与边界**  
Runtime Controller 拥有最终执行状态；Planner 与模型只提交计划/动作提议。

**异常与恢复**  
按参数、权限、网络、模型、工具、验收或未知副作用分类；仅对幂等或可证明安全的动作重试。

**安全与架构不变量**  
状态必须可追溯和可恢复；未知副作用不得盲目重放；历史版本与证据不可被新版本覆盖。

**验收标准**  
验收目标：保存 DAG 节点状态、恢复游标和必要输入输出引用。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
