# EvoAgent 专项详细设计｜02_记忆上下文与个性化
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### M-01｜用户长期记忆

**设计目标与范围**  
稳定偏好、长期约束和可复用授权偏好。

**正式设计决策**  
记忆和上下文必须带命名空间、来源、时间、可信度与隐私级别；摘要不能取代原始事实。

**输入与输出契约**  
输入：命名空间、来源材料、访问权限、当前任务预算和 ContextManifest。输出：记忆条目、检索结果、压缩上下文、冲突记录和生命周期事件。

**标准处理流程**  
检索候选 → 过滤权限/时效 → 去重和冲突检测 → 重要性排序 → 装配/压缩 → 记录来源与版本 → 评估效果。

**控制权与边界**  
Context & Memory Manager；专家可提供策略但不能绕过命名空间和隐私门禁。

**异常与恢复**  
来源缺失、冲突或低置信时降权/隔离；删除和过期按来源链传播。

**安全与架构不变量**  
关键结果必须有来源、版本和验收证据；无法证明时明确标注未知，不把假设写成事实。

**验收标准**  
验收目标：稳定偏好、长期约束和可复用授权偏好。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
