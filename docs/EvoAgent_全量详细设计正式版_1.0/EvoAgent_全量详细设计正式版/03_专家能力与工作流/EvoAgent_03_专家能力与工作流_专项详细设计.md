# EvoAgent 专项详细设计｜03_专家能力与工作流
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### C-01｜专家注册表

**设计目标与范围**  
领域、能力、工具、工作流、记忆、模型和评测声明。

**正式设计决策**  
能力资产必须版本化并声明依赖、适用范围、权限、验收和回滚；未验证资产不能进入稳定路由。

**输入与输出契约**  
输入：资产定义、工具契约、依赖图、来源轨迹、目标平台和评测套件。输出：版本化能力资产、依赖清单、适用范围、测试报告和回滚引用。

**标准处理流程**  
登记候选 → 校验契约/依赖 → 隔离运行 → 独立评测 → 批准 → 激活 → 观察退化 → 冻结/回滚/退役。

**控制权与边界**  
KCLG/Asset Governance 管理资产；领域专家负责内容，受保护发布控制器决定稳定版本。

**异常与恢复**  
缺依赖、契约不兼容或评测不足时保持候选状态；不得覆盖历史版本。

**安全与架构不变量**  
关键结果必须有来源、版本和验收证据；无法证明时明确标注未知，不把假设写成事实。

**验收标准**  
验收目标：领域、能力、工具、工作流、记忆、模型和评测声明。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
