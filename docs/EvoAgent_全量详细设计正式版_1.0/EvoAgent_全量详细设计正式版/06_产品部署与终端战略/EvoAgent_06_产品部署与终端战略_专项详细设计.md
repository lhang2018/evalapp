# EvoAgent 专项详细设计｜06_产品部署与终端战略
**正式设计基线 1.0｜2026-10-20**

本卷是正式详细设计，不是原型草稿。所有模块遵循统一任务身份、不可变版本、最小权限、证据可追溯、独立验收和失败可恢复原则。

### P-01｜产品定位与价值主张

**设计目标与范围**  
个人通用智能体；真实任务完成、可靠复用和可验证改进。

**正式设计决策**  
进化以可验证的真实任务收益为标准，不以自我修改次数或模型自评为标准。

**输入与输出契约**  
输入：产品目标、用户场景、设备/部署约束、已确认决策。输出：功能边界、版本化需求、验收标准、依赖和风险。

**标准处理流程**  
需求登记 → 价值与场景核验 → 能力/设备边界划分 → 依赖与风险评估 → 验收设计 → 版本化记录。

**控制权与边界**  
产品治理与架构治理；终端实现由对应客户端模块负责。

**异常与恢复**  
发生架构冲突时建立 ADR；未确认假设标为待决策，不作为硬依赖。

**安全与架构不变量**  
关键结果必须有来源、版本和验收证据；无法证明时明确标注未知，不把假设写成事实。

**验收标准**  
验收目标：个人通用智能体；真实任务完成、可靠复用和可验证改进。验证至少覆盖正常路径、异常/边界输入、重启或重复请求（适用时）、权限/隐私拒绝和版本兼容；结果可由自动化测试或明确的人工验收步骤复现。

**实现约束与依赖**  
本模块必须通过统一 task_id/run_id、版本清单、结构化事件和审计链关联运行；接口需声明版本、错误码、超时和幂等语义。变更范围通过能力依赖图确定，不能静默改变稳定版本。
