# 异步审批与原动作恢复交付

日期：2026-10-22（Asia/Shanghai）。ALN-04 第二段，基于上一轮尚未提交的运行身份与问答实现继续开发。本轮未提交或推送，保留其他 Android 通知在途改动。

## 当前行为

默认 confirm 策略下，任务调用需要确认的工具而没有同步确认回调时，创建持久化 pending 审批并挂起任务。批准后继续保存的原动作；拒绝则取消任务。显式 deny 策略、工具拒绝策略、专家允许列表和副作用对账限制仍参与裁决。

| 链路 | 本次实现 |
|---|---|
| 授权绑定 | 保存完整 binding_json 和规范化 SHA-256。绑定 task_id、操作名、全部实际参数、作用域、工具版本、声明权限和风险；工作流再绑定工作流版本与节点，ReAct 绑定迭代位置。显示摘要截断不影响授权匹配。 |
| 参数与节点 | 工作流在解析上游输出参数后才请求审批。节点要求确认与高风险工具确认统一通过网关裁决，一个动作不会因两道确认产生两次同义审批。函数节点的确认同样持久化，仍依赖注册代码及工作流版本可信。 |
| 一次性消费 | pending → approved / denied；approved → used / revoked。决策和精确动作消费均由 SQLite 写事务保护，跨连接并发只有一次新决策、一次消费。默认请求有效期 15 分钟，取得写锁后才检查到期时间，避免排队期间过期仍放行。 |
| ReAct 继续 | 保存 pending_action，恢复先执行该动作，再请求下一次模型决策；不会为重新生成动作多记一次模型调用。审批等待不算工具成功或业务失败，不推进计划。 |
| DAG 继续 | 已成功节点输出和累计预算保留；并行等待节点分别生成审批，当前审批全部批准后调度恢复。过期节点重新发起审批；不把并行节点执行承诺为原子事务。 |
| 决策恢复 | 批准后创建子运行，保留父运行历史。决定已写库但尚未调度时，重启后重试同一批准可继续安排执行；重复已消费的批准不再运行。未决副作用阻止自动恢复，批准记录保留，先完成对账。 |
| 拒绝与取消 | 管理员拒绝当前待审批动作时，事务内取消任务并撤销其他待批/未消费授权；普通取消也清空等待引用并撤销未用授权。旧请求不能再批准执行。 |
| 版本与旧库 | Schema v3 为审批追加 action_digest、binding_json、requested_run_id，旧审计记录保留。工具版本改变需新审批；新运行清单刷新实际工具版本库存。 |
| 操作入口 | 新增管理员单条审批详情和决策 API；CLI 可列审批、批准或拒绝。Android 持久化并显示等待审批编号，API 客户端支持显式管理员凭据调用；本轮未增加完整管理员审批页面。 |

主要实现：[审批实体](E:/evalapp/evoagent/core/approvals.py)、[持久化事务](E:/evalapp/evoagent/core/persistence.py)、[权限裁决](E:/evalapp/evoagent/core/permissions.py)、[工具网关](E:/evalapp/evoagent/tools/registry.py)、[控制器](E:/evalapp/evoagent/core/controller.py)、[ReAct](E:/evalapp/evoagent/react/engine.py)、[DAG](E:/evalapp/evoagent/workflows/engine.py)。

## 使用入口

1. `GET /tasks/{task_id}`：通过 waiting_approvals 查找当前任务等待的审批。
2. `GET /approvals/{approval_id}`：管理员读取 action_summary、完整 binding_json、作用域、状态和有效期。
3. `POST /approvals/{approval_id}/decision`，正文 `{"approved":true}` 或 `{"approved":false}`。新决策返回 202，同向重复决策返回 200；格式错误 400，未知 ID 404，过期/冲突/非当前等待边界 409。202 表示已接受决策，执行进度继续查询任务。
4. CLI：`python -m evoagent.cli approvals <task_id>` 查看全部字段；`python -m evoagent.cli approval-decision <approval_id> approve` 或 `reject` 决策并等待恢复结果。

HTTP 详情和决策均要求 admin，operator 请求被拒绝；沿用现有未配置令牌时的本地开放模式。客户端管理员凭据仅随显式审批调用发送，不写入其他普通请求。完整参数用于批准前审阅，不能只根据截断的摘要判断操作范围。

异步审批只适用于带任务身份的执行路径；没有任务身份/审批存储的高风险调用仍拒绝。同步 confirm 回调和显式策略继续保留；回调明确拒绝不会自动改成待批请求。无权限控制器时，独立 WorkflowEngine 仍可使用既有显式 confirm 回调。
