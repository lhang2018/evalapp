## 本轮核对发现的口径问题

1. **“observability 全域零入口”不成立**。当前 feedback_api 已在 server 注册，并有 3 处 observability.feedback 导入。准确缺口是 **16-P 聚合观测 API 未装配及端侧证据接线**，不是整个 observability 都不可达。30-A 验收应按具体能力逐项核查，不能用“存在任意导入”证明全域完成，也不能因模块未在 app 顶层导入判定无入口。
2. **根 README 与协作入口仍写 candidate/41 卡**，与已发布基线及新卡冲突。本轮同步入口；早期差距报告加历史标记，保留原始审计证据。
3. **17 用例映射的采证步骤仍建议把组件断言和历史回滚记录整理成 integration 通过记录**，虽然文首撤回了旧 8 条通过。该建议仍会制造误验收，本轮移除；真实场景未执行继续 not_run。

核对方式：固定提交读取 workboard 和入口 AST 导入；执行产品矩阵结构/require-pass 及发布证据结构/require-release。结果分别退出 **0 / 1 / 0 / 2**：后两种“要求全部通过”的非零是预期的未验收状态，不能解释为校验器故障。没有新跑业务全量、没有回填产品证据。
