## 2. 执行规则与边界

### 状态规则

工作包依次使用：待细化 → 就绪 → 实现中 → 待验收 → 已验收；依赖未满足时标阻塞并指出具体依赖。**这 23 个工作包是待实施计划，不因写进文档而自动完成。**

每个工作包交付至少包括：

1. 一项可观察的行为变化及对应设计 ID。
2. 变更涉及的契约/迁移、对旧版本的兼容或拒绝策略。
3. 正常、拒绝/失败、重启/重复请求等与其风险匹配的验证。
4. 精确源码版本、测试命令/结果、实际产物或事件/审计引用。
5. 回滚路径与剩余限制；不把字段有值、接口存在视为行为已验收。

### 既有文档如何衔接

- 正式版 1.0 是需求目标；现状报告是有时间边界的证据快照；本计划负责排序、认领和关闭标准。
- ALN 编号是本次审查工作包，不替换稳定主题 ID，也不新增第二套业务契约。
- 对应旧 T0/T1 的修复主要落 ALN-01..04；旧 T3 落 ALN-09..10；旧 T2 落 ALN-13..15；旧 T4/T5/T6 由其余工作包拆分。
- 旧 F/WP 的“已完成”只说明当时交付范围，不自动满足本计划的更完整验收。例如 F-03 已有账本实体，不代表未知副作用场景已安全。
- 新功能优先通过域 schema、路由注册表等现有扩展点；需要修改共享 controller/registry/contract 时集中处理，同一文件的变更要保持一致。
- 不要求为了“八服务”拆微服务；不要求 Android 首发等待 Windows/平板。分别报告阶段完成与全量目标完成。
- 不估算未经团队容量/PoC 验证的人日和日期；先用下述依赖与退出条件推进。

### 需要细化而非直接照抄的决策

ALN-00 为这些决策建立版本化记录，由对应责任领域细化实现，不以空白原则文替代接口规范：

- Goal：09 卷十态为明确基线，补允许转移、拥有者、期限、停止和授权传播；数值阈值要有测试与测量依据。
- 隐私/同步：契约四值与 legacy 内部字段给出显式映射、往返序列化和迁移；已实现 acknowledged 不能继续记为缺失。
- 工具幂等：state-check 只有存在真实状态查询证据时才能判安全；不得无条件映射为 idempotent。
- 资产 namespace 与 memory scope 是不同维度，保留明确命名与适用规则，不强行合并。
- Runtime Manifest.workflow_ref：正式例子为 id/version 字符串，当前代码为对象；确定规范格式、兼容读取和写入版本，避免默默改例子。
- 故障归因等级与候选风险等级分开命名，禁止同名 L 级混用。
- 候选/发布：实际候选内容、签名载荷、门禁权限与 stable 指针的信任边界写清楚。
