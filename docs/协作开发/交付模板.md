# 任务交付模板与检查命令

以下模板可直接复制到任务卡的交付记录或 PR 描述。PR/消息是否发布仍由实际开发者的授权范围决定。

```markdown
任务：ALN-xx / 子任务名
负责人：
审阅人：
基线 commit：
分支与最终 commit：
认领状态：

触发场景与行为变化：
- 输入/触发：
- 修改前：
- 修改后：

范围：
- 独占模块：
- 共享文件补丁与整合角色：
- 新增/修改契约，提供方与消费方：
- 数据迁移、旧格式兼容或明确拒绝：

验证证据：
- 正常路径及实际产物/事件/运行引用：
- 拒绝/失败/重复/并发/重启（按本任务风险选择）：
- 命令、结果、日志位置与对应源码 commit：
- Mock / 本地组件 / 真机 / 真实供应商的验证边界：

回滚与未完成事项：
- 回滚触发、操作及验证：
- 保留的限制、后续 ALN 和依赖：
- 影响的主题/实体/ADR/契约/系统验收条目：

审阅结论：待审 / 需修改 / 本卡验收通过
整包结论：仍实现中 / 附完整关闭证据后验收
```

## 合并前命令

集成人在仓库根目录运行；个别任务先执行其任务卡中的专项，最终合并候选再跑全量。

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
python -m pytest -q
python tools/verify_claims.py
python tools/scan_all_ledgers.py
python tools/check_gap_closure.py
python tools/check_collaboration_plan.py
python .planning/2026-10-22-design-alignment/verify_alignment_plan.py
git diff --check
Push-Location android-app
npm.cmd run test:offline
npm.cmd run typecheck
Pop-Location
```

运行边界专项：

```powershell
python -m pytest tests/test_execution_boundaries.py tests/test_run_continuation.py tests/test_async_approvals.py tests/test_auth_rejection_transport.py -q
```

认领表更新后执行 `python tools/check_collaboration_plan.py --render` 重新生成开发任务认领表.md，并检查 JSON/Markdown 同步。该检查器只核对计划结构和分工，不执行业务测试或发布操作。

候选基线摘要校验使用 `python tools/check_collaboration_plan.py --verify-snapshot`；后续代码变更使历史摘要不一致是正常的，应发布新版本的基线清单，而不是修改历史摘要冒充未发生变化。
