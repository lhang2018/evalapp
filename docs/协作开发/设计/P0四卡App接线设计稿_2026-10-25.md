## 挂载点与数据流（App.tsx）

### 1. 入口区：模式判定（23-B）

```
goalDraft 变更（或提交时）→ classifyMode(text, { explicit: modeOverride })
  stickyMode(previous, explicit) 保持用户显式覆盖
chat → 现有轻量路径（runOffline/直接问答），不打扰
work → 现有 submitGoal 路径，且：
  聊天会话轮次（本轮 chat turns）→ buildTaskSeed(turns) → seed 附到提交
```

- 挂载点：`submitGoal`（App.tsx:625 附近）前置一步 + 输入框上方一行模式
  徽标（chat/work + signal 文案），点击可显式切换（写入 modeOverride state）。
- 23-A 对接面：`buildTaskSeed` 产出的 `TaskSeed{goal,constraints,corrections,
  completedDigest,pendingPoints}` 直接映射 23-A 契约的约束/背景字段；
  `noRepeatGuard(seed).ok===false` 时拒绝提交并提示重复。

### 2. 任务列表行：状态映射（23-D）

```
localTasks.map(task) → taskViewOf(task) →
  行首徽标 = view.label；state==='needs_you' 高亮 + wait.reason 行
```

- 挂载点：App.tsx:1394 `localTasks.map` 行渲染替换现有 status 文本。
- 不改 LocalTask 契约；`wait.reason` 点击跳到既有审批面板/澄清入口。
- 17 用例 UX-08 断言（29-A 骨架）在此执行。

### 3. 权限/更新中心：能力六档（24-B）

```
服务端 GET /capabilities/status → CapabilitiesStatusPayload
projectUserCapabilities(payload, { accessibilityAvailable }) → UserCapabilityView[]
```

- 挂载点：权限 tab 新增"能力状态"卡；每能力一行
  `state 徽标 + reason + recovery（可点）`。
- `canExecute(view)` 为 false 的能力，入口按钮禁用并展示 recovery。
- accessibilityAvailable 复用 App 既有的 `deviceAvailable` 状态，不新探测。

### 4. 任务卡详情：反馈入口（29-C）

```
POST /feedback { category, text, task_id: task.server_task_id,
                 run_id: task.current_run_id }
```

- 挂载点：每个终态/失败任务卡尾部"反馈问题"入口；提交结果显示
  aggregated=true 时提示"已并入同类反馈"。
- 文本框本地不做秘密检测（服务端 scrub+拒绝是权威），但提交失败
  （含凭据拒绝 400）按服务端错误文案如实展示。
