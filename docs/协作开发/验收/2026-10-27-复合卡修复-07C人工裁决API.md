## 修复的缺口

原卡保留缺口之一：**`WAITING_USER`（reconciliation）人工裁决消费入口缺失**——
门禁只写 `waiting_request(phase=reconciliation)` 与未决目标清单，没有按目标裁决的
结构化入口。本次补齐该缺口。

## 实现

1. **幂等域表** `evoagent/core/schema/reconciliation.py`（`DOMAIN=reconciliation_decisions`）：
   `reconciliation_decisions(task_id, target_id, target_kind, decision, actor, reason,
   created_at, data)`，主键 `(task_id,target_id)`；靠 `core/schema` 自动发现，无迁移、无版本号。
2. **裁决存储** `evoagent/core/reconciliation_decisions.py`：
   - `pending(task)`：仅当任务 `WAITING_USER` 且 `phase=="reconciliation"` 可裁决；
     未决目标 = 未声明/未决/歧义**效果**（effect_id）+ 未执行**步骤**（step_id）；
   - `record(...)`：只允许清单内目标、取值 `executed/not_executed/retry`、必须记录
     actor/reason；同一目标改判需 `override=True`（否则冲突），相同裁决幂等；
     写事务为 `BEGIN IMMEDIATE` + 回滚；
   - 返回 `resume_ready/auto_resumed=False`，**只记录证据、不改任务状态、不触发重放**。
3. **API** `evoagent/api/reconciliation_api.py`（server.py 一行 import 注册）：
   - `GET /tasks/{id}/reconciliation`：只读未决目标 + 已记录裁决；
   - `POST /tasks/{id}/reconciliation/decisions`：admin 记录逐目标裁决
     （冲突 409、非法 400、未知任务 404；operator/非归属主体按既有规则 403）。
