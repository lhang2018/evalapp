## 二、纪律落点：未运行不记通过

EA-REL-005 原文的三条硬规则被直接实现为代码约束：

| 原文规则 | 实现 |
|---|---|
| "测试尚未运行时标记为未测试" | 状态只有 `pass`/`fail`/`untested` 三值；`untested` 的 evidence 必须为空，否则判自洽错误 |
| "没有验证过的能力不得标记为正式支持" | `pass` 必须有非空 evidence，且每条含 `kind`/`ref`/`result` 三要素，缺一即判错 |
| "任何硬性门禁失败，都不能通过计算综合平均分来放行" | 硬性门禁（G0/G1/G2/G3/G5/G6/G7）任一 `fail` → 整体不可发布；且 `untested` 与 `fail` 同等对待 |
| "发布门禁不是一个综合分数，每一道门禁都有自己的否决权" | 校验器不做任何加权或求和，只做逐项判定与合取 |

另加一条跨表一致性约束：**台账 `baseline.published_commit` 为空时，G6 不允许标为 `pass`**
——没有已发布版本就无法证明"已发布版本可以回滚"（G6 原文要求）。

## 五、首条真实任务链

EA-REL-005 §四指定用**"资料整理并生成报告"**作为第一条主验收链：

- **正常路径 8 步**：提交资料 → 建立任务记录与验收契约 → 调用真实模型与资料处理工具 →
  保存运行状态与关键事件 → 生成实际文件 → 独立验收器检查 → 交付并展示验收状态 → 记录供质量分析。
- **异常路径 10 类**：资料不完整、模型超时、工具失败、预算耗尽、用户取消、应用中途退出、
  验收失败、文件生成失败、网络中断、运行状态无法确认。原文规则："系统可以报告部分完成，
  但不得用部分完成冒充全部成功。"
- **每次正式验收运行须保存 8 类证据**：任务与运行标识、模型与工具配置、实际执行结果、
  关键状态变化、实际产物、验收规则及结果、错误恢复与预算记录、对应测试版本。

本卡只把这些要求**结构化落表**，尚未产生任何一条真实任务链的运行证据。

### 判别力证据（变异测试 7/7）

向校验器注入 6 类缺陷，验证测试确实能抓住，而不是"测试全绿"的自证：

| 变异 | 注入的缺陷 | 捕获 |
|---|---|---|
| M1 | 去掉"pass 必须有证据"检查 | ✓ test_pass_without_evidence_is_rejected |
| M2 | 去掉"untested 阻止发布"判定 | ✓ test_untested_gate_is_not_counted_as_passed |
| M3 | 去掉 G6 与 published_commit 的交叉校验 | ✓ test_g6_pass_without_published_commit_is_rejected |
| M4 | 去掉"untested 挂证据"自洽检查 | ✓ test_untested_with_evidence_is_rejected |
| M5 | 门禁编号校验改为只数数量 | ✓ test_renumbered_gate_is_rejected |
| M6 | 范围项编号校验改为只数数量 | ✓ test_renumbered_range_item_is_rejected |

**首次变异测试暴露了本卡自身的一处真实弱点**：原 `test_untested_gate_is_not_counted_as_passed`
只把 G0 置为 untested，而仓库表里其余门禁本就未通过，导致"未测试阻止发布"这条逻辑
从未被真正单独验证——M2 注入后测试仍全绿。已改为"其余七门禁与十三项范围全部置为通过、
只留 G0 未测试"的隔离写法，并补写 `test_renumbered_gate_is_rejected` 与
`test_renumbered_range_item_is_rejected` 两个改号用例（M5/M6 首版是等价变异，无判别力）。
修复后 14 个测试通过、7/7 变异被捕获。
