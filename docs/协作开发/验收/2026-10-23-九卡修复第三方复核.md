## 二、发现一个修复缺口（PR-04 残留 → 已在 5847f3f 修复）

**场景**：A 以 `identity=user-a, task_id=task-1` 写入 TASK 作用域条目；
B 以 `identity=user-b`（同 task_id）携带 A 的 memory_id 写入不同内容。

- 期望：拒绝（「不可覆盖其他身份的记忆」）。
- 复核时点（34b5fac）：写入成功，A 的条目内容被替换（读回验证
  `content='B 伪造'、user_id='user-b'`）。

**根因**：`_identity_visible` 按 item 的 `scope` 取单一作用域键（TASK→`task_id`），
同一 task 内不同 user 互相「可见」，`user_id` 差异不参与覆盖判定。修复只挡住了
作用域键不同的场景（USER 作用域跨 user 覆盖已被正确拒绝，探针验证过）。

**后续闭环**：本报告初稿期间，并行会话提交 `5847f3f` 引入 `_owner_partition`
——可见性判定改为完整属主分区比对（TASK 作用域比对 user/project/session/task
四元组）；本复核人在当前 HEAD（05a7cf4）用探针 M3 原场景复验：**已拒绝**。
该修复作者仍为 codex-runtime，按纪律本复核以探针复验确认修复有效，
ALN-05-M 的 PR-04 切片据此可视为已复核闭环。

**定性（历史）**：34b5fac 时点为 P2 缺口；5847f3f 后闭合。

**顺带观察（非缺陷）**：同 user 对同 fact_key、同 ID 条目的改写走
`INSERT OR REPLACE` 直接生效，未产生 fact 冲突记录——ID 显式相同时按
「作者修订」处理是可解释语义，记录备查。
