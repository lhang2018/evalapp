## 任务桥接说明（诚实登记）

设备任务列表只含设备提交的本地任务，服务端造的 WAITING 任务设备不可见；
为使审批面板上屏，通过 `run-as` 向设备 AsyncStorage 的 `offline_state_v1`
注入三条/一条本地任务映射（`server_task_id` 指向服务端等待任务，状态
SUBMITTED）。此为测试夹具动作：四路径的全部 UI 交互（凭证输入、详情
读取、按钮决策、离线降级、过期闸门）与服务端语义均为真实行为，源码
零改动。

## 四路径结果

### 1. 批准路径 → 任务推进 SUCCEEDED

- 面板输入凭据后自动读取详情，展示完整 binding（任务/操作/有效期/
  动作摘要校验值/长参数全文）。
- 点「批准此动作」→ 服务端 `controller.decide_approval` 受理 → 审批
  `used` → 任务 `a15c5d4718e3` **SUCCEEDED**，result
  "工作流完成: probe=审批后动作已执行"（批准后工具真实执行）。
  断网路径复验同一语义（`9f9ce3874a88` SUCCEEDED，`apr_70426ad7` used）。
- 证据：`.planning/2026-10-24-aln04ui-device/final-approve.png`、
  server.log、approvals 列表（used）。

### 2. 拒绝路径 → 服务端取消

- 任务卡面板「拒绝并取消任务」→ 审批 `apr_ce37cb2a` → **denied**，
  任务 `65ed5ad7b9f6` → **CANCELLED**（沿用服务端取消原任务语义）。
- 设备 UI 同步显示「结果: 用户拒绝审批，任务已取消」+ DONE
  （dump `a15/a16`）。

### 3. 断网 → 详情保留、按钮停用、恢复后可批

- `adb reverse --remove tcp:8300`（服务端不可达）后点「刷新审批状态」：
  面板显示 **"详情待本次会话刷新核验，审批按钮已停用。"** +
  **"离线：可查看已读取详情，联网后刷新审批。"**，已读取详情（待审批
  + 完整 binding）原样保留（dump `f4`，截图 `f4.png`）。
- 恢复 `adb reverse tcp:8300` → 刷新成功 → 详情回到「待审批」→
  批准 → 任务 `9f9ce3874a88` **SUCCEEDED**。
- 回包丢失（请求已生效但回包丢失）的中途断网时序由
  `approvals.test.ts` 12 项状态/传输夹具覆盖；真机以"离线降级+恢复"
  为准。

### 4. 过期 → 决策闸门停用，任务保持等待

- 注入过期：`UPDATE approvals SET expires_at=<past>`（与
  `test_expired_pending_request_cannot_be_approved` 同法）→ 面板显示
  **"审批 apr_… · 已过期"**，点「批准此动作」无任何状态变化
  （`canDecide()` 要求 pending+未过期，本地闸门直接不发起请求），
  任务保持 SUSPENDED，服务端审批状态 expired（dump `a5/a6/a7`）。
- 自然 TTL 过期：批准路径第一枚审批 `apr_9729b387` 在操作间隔中自然
  过期（TTL 到期），同样无法决策；`POST /tasks/{id}/resume` 后状态机
  正确重请求新审批（`apr_912df78c`）并可正常批准——过期→重请求链路
  一并验证。
