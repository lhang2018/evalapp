# ALN-11-A：Android 真实制品下载、装载与回滚

建议角色：android/release。前置 ALN-03-S 已交付服务端规范化签名与制品校验，本卡消费其清单字段，在端侧完成真实字节下载、受信公钥验签、暂存切换与健康回滚。原生 APK 更新仍走平台机制，本卡只处理可版本化的能力/策略/工作流包。

## 目标

让客户端不再信任服务端下发的 `signature_ok` 布尔值：断点下载真实制品字节到暂存文件，用内置受信公钥验证真实字节，检查空间、权限与版本兼容，通过后才原子切换槽位；装载后自动健康探针，失败回到 last-known-good。回执绑定实际激活版本，重复上报幂等。

## 写入边界

独占 `android-app/src/update/`（新增下载、验签、暂存、回执模块）、`android-app/test/update/`；必要时只接线 `android-app/App.tsx` 的更新入口，不改动离线队列与设备通知等并行会话文件。

`evoagent/release/delivery.py` 如需下发制品地址/签名 envelope，先以只增字段方式协调，不改变既有回执语义。原生文件系统/网络适配通过注入端口实现，测试使用纯 Node 替身，不引入新依赖。

## 实施顺序

1. 定义制品交付契约：URL/大小/`sha256`/签名 envelope/签名密钥 ID/最低 App 版本/所需权限与工具契约；`capability_slot` 之外仍拒绝客户端二进制。
2. 实现断点下载：Range 拉取、`.part` 追加写、进度检查点持久化、总大小与上限约束；断网/进程重启后从已写偏移继续。
3. 实现端侧验签：受信公钥钥匙环（key_id、有效期、撤销位），当前交付采用 RSA PKCS#1 v1.5/SHA-256 验证真实字节摘要与规范化元数据；缺文件、坏摘要、坏签名、未知/撤销密钥均拒绝。原草案的 Ed25519 尚未实现，算法扩展需单独设计与验收。
4. 完成后才把 `.part` 原子改名为槽位制品，装载策略/工作流/能力引用；空间不足或兼容失败不改变活动槽。
5. 健康探针失败自动回滚；回执带 release/version/digest/key_id，持久化未确认回执并幂等重放。

## 验收

- 真实字节与清单不符、签名错误、密钥未知或撤销时不得进入激活态。
- 断点下载在中断后从已写偏移恢复，不重复写坏文件；空间不足不激活。
- 健康检查失败恢复旧行为，last-known-good 不被新版本覆盖。
- 回执绑定实际版本且重复上报不产生重复业务效果。
- 行为随激活版本变化（策略/能力包引用切换），不是只切换元数据。

## 交付

端侧下载/验签/暂存/切换/回执模块、注入端口与专项测试；服务端真实制品地址下发与多设备灰度联调记录未完成项，不把服务端 HMAC 秘密下发给客户端。

可复制给接手者：

> 认领 ALN-11-A。读本卡与 ALN-03 交付记录，先锁定端侧制品与签名 envelope 契约，再实现断点下载到暂存文件、受信公钥验签真实字节、空间/权限/兼容检查和原子切槽。独占 android-app/src/update 与 test/update；共享 App 入口只做必要接线。用坏签名/缺文件/低空间/中断恢复证明不会错误激活。
