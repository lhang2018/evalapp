# ALN-18-D：补丁事务日志与中断恢复

建议角色：runtime。承接 ALN-18-C：`coding_patch` 已能预检、写后核验与进程内回滚，但进程在写盘中途被杀（断电、OOM、Ctrl-C）时没有持久化记录，重启后无法判断哪些文件已被改、应恢复到什么状态。

## 目标

- `coding_patch` 在写盘前先把事务日志原子落盘（临时文件 + `os.replace`），日志记录每个文件的 `path`、`sha256_before`、`sha256_after` 与原始内容。
- 全部写盘并核验成功后删除日志；进程内回滚成功后也删除日志；回滚失败时**保留**日志供后续恢复。
- 新增 `coding_patch_recover`：
  - 扫描日志目录，逐文件比对当前摘要：等于 `sha256_after` 则恢复原始内容；等于 `sha256_before` 视为已恢复；两者都不等则记为**冲突，不覆盖**。
  - 全部文件解决（恢复或本已处于前状态）后删除该日志；存在冲突则保留日志并如实报告。
  - `dry_run=true` 只报告将执行的动作，不写盘、不删日志。
- 证据逐文件给出 `file`、`sha256_before/after`、`action`（`restored`/`already_before`/`conflict`），并汇总 `restored`/`conflicts`。
- 日志目录在项目根 `.evoagent_patch_journal/`，同时加入符号扫描跳过目录；成功路径不留残留文件（空目录移除）。

## 写入边界

可独占修改：

- `evoagent/tools/coding.py`
- `tests/test_coding_tools.py`
- `docs/协作开发/交付/ALN-18-D-*.md`

不得触碰：注册表、`contract.py`、`app.py`、专家注册表及执行路径共享文件。本卡不接线。

## 验收

- 正常补丁成功后日志目录无残留文件；失败回滚成功后同样无残留。
- 模拟中断（人工放置日志 + 文件处于 after 状态）后 `coding_patch_recover` 恢复原文并删除日志；再次调用为空操作成功。
- 冲突保护：文件内容既非 before 也非 after 时不被覆盖，日志保留，返回冲突明细。
- `dry_run` 报告动作但不修改文件与日志。
- 损坏/不可解析日志跳过并报告，不中断其他日志恢复。
- 能力包版本升到 `1.3.0`，`rollback_version=1.2.0`，工具 ID 八个。
- 既有 25 项测试不回归；新增专测覆盖恢复正常、冲突、dry-run、损坏日志与残留清理。
