# ALN-07-E 副作用账本对账（计划↔已执行副作用）

负责人claude-main；状态accepted（既定纯读切片）。codex-runtime发现六组问题并修复26aaec7，claude-main已第三方复核接受，见[独立复核](../验收/2026-10-24-ALN-07-E修复第三方复核.md)；实际运行时消费另验。ALN-07 整包第四项，接续 07-P/07-W/07-T/07-R。
07-T 给出「哪些步骤已完成或未完成」，本卡回答 07-T 回答不了的下一个问题：
**这些步骤实际有没有按计划产生副作用，产生了哪些没在计划里的副作用。**

## 目标

回答 07-T 答不了的问题：计划的每一步，**实际有没有按声明产生副作用，
以及有没有产生计划之外的副作用**。产出一份可判定的纯读对账报告。

### 缺口（2026-10-24 核实）

全库不存在任何「计划↔副作用账本」的自动对账实现（`reconcile_plan`
/ `plan_reconcile` / `expected_effects` 均无命中）。计划（ExecutionPlan）
与副作用账本（SideEffectLedger → `task_side_effects`）目前是两套互不相干的数据：
一个计划步骤声称要调用 `file_write`，实际账本里没有任何记录时，
没有任何东西会发现。ALN-07 整包 next_step 明示此项为遗留待办。

## 范围

新增**纯读**对账服务 `evoagent/planning/reconcile.py`：

- `SideEffectReconciler.reconcile(plan, records) -> ReconciliationReport`
- `records` 取自 `SideEffectLedger.history(task_id)` 的投影
  （字段：`effect_id / task_id / tool_id / status / idempotency_key /
  effect_summary / run_id`）
- 按 `tool_id` ↔ `PlanStep.tool_hint` 归因，产出四类明细：
  - `matched`：计划声明且账本存在已确认记录
  - `undeclared`：账本有执行、计划未声明该工具（越权/计划失真）
  - `unexecuted`：计划声明了该工具、账本无记录（声称要做实际没做）
  - `uncertain`：账本状态为 `unknown`/`planned`/`submitted`（副作用结果未决）
- `summary` 汇总四类计数与总检出项，`ok` 表示无 undeclared、无 unexecuted、
  无 uncertain 的理想一致状态

## 验收（逐条留证）

1. **完整归因**：每一条账本记录必须落到某个计划的步骤上，或明确归入
   `undeclared`；任何记录都不得被静默丢弃。
2. **未执行不冒充成功**：计划步骤声明了工具提示但账本无记录 → 进
   `unexecuted`，且报告 `ok=False`。
3. **未决不算完成（fail-closed）**：`unknown`/`planned`/`submitted`
   状态的记录一律归 `uncertain`，**绝不计入 `matched`**——"没确认"不等于"没发生"。
4. **越权检出**：账本出现计划未声明的 tool_id → `undeclared`，`ok=False`。
5. **确定性**：打乱 plan 步骤顺序与 records 顺序，报告内容（排序归一化后）
   完全一致——不依赖输入次序。
6. **纯读（零写入权限）**：不调用 `SideEffectLedger.transition / reconcile /
   record / begin / finish` 中任何一个；对账不修改账本、不解除 pending、
   不裁决任何副作用。以只读夹具（写入即抛错）证明。
7. **序列化往返**：`to_dict` / `from_dict` 无损，各类明细与 summary 保持。

## 写入边界

**纯读、零写入权限**：本卡不调用 `SideEffectLedger` 的 `transition /
reconcile / record / begin / finish` 中任何一个；对账不修改账本、不解除
pending、不裁决也不补偿任何副作用。写入边界以「写入即抛错」的只读夹具证明。

以下明确保留（不属本卡）：

- **不接运行时**：由谁在对账后做什么（是否重试、是否告警）不属于本卡。
- **不改账本**：本卡不 reconcile 副作用、不释放 pending、不补偿。
- **不做语义等价判断**：`file_write` 与 `file.append` 是否等价由调用方判定，
  本卡只按 `tool_id` 字面归因，并如实把未匹配项暴露出来（不猜）。
- ALN-07 整包的工作流/轨迹/恢复的实际运行时消费仍属其它卡。
