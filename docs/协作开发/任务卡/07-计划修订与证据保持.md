# ALN-07-P：计划修订与已完成证据保持

建议角色：runtime。整合依赖 ALN-02-A（副作用账本已交付，`22c50ca`）与 ALN-04-R（运行接管已被接受）；本卡只消费这两项的已交付接口，不等待 ALN-06/ALN-08 整包关闭，也不对它们做任何结论。

## 目标

交付 ALN-07 三项中的第二项「修订保持约束和已完成证据」。现状：`ExecutionPlan.adjust`（`evoagent/planning/planner.py`）全仓库只有一个调用方（`react/engine.py` 的连续失败恢复），且实现与自身 docstring 相反——`completed_work` 从**新步骤列表重算**，修订一旦替换、重写或重排已完成步骤，已完成证据即丢失；`original_goal` 与 `immutable_constraints` 也无任何防改写校验。后果正是 ALN-07 关闭标准禁止的：失败分支修订后续跑**可能重放成功副作用**。

本卡交付：修订分级原语（追加恢复步骤 / 替换未开始步骤 / 重规划未开始子图 / 目标与约束变更需人工授权）、约束与证据不变量校验（违约即拒绝修订并留事件）、修订与副作用账本的衔接判据（接口先行，接线补丁另交）。

## 写入边界

可独占：`evoagent/planning/planner.py`（非共享文件）、拟新增 `evoagent/planning/replan.py` 或同职责模块、`tests/test_plan_revision.py`。

`evoagent/react/engine.py`、`evoagent/core/controller.py` 属 runtime 共享文件：只提交「接线需求＋小补丁」，由 runtime 线串行合入；不能另写第二套计划权威。副作用状态读取走 `core/side_effects.py` 既有接口，不私建表、不改账本语义。

## 第一份交付：分级语义与不变量夹具

先定四级修订的不变量表，再用夹具证明现状违约：

| 级别 | 场景 | 必须保持 | 必须拒绝 |
|---|---|---|---|
| append | 连续失败后追加恢复步骤 | 全部既有步骤与证据 | 恢复步骤依赖不存在步骤 |
| replace | 替换**未开始**步骤 | original_goal、immutable_constraints、completed_work 只增不减 | 替换已开始/已完成步骤 |
| replan | 重规划未开始子图 | 已完成子图与验收条件 | 静默改写目标或约束 |
| reauthorize | 目标/约束变更 | 原目标留痕 | 无人工授权的目标改写 |

与账本衔接：被替换/重排的步骤若已有 `submitted`/`unknown` 副作用，修订必须经对账判据，`unknown` 不得当作未执行。

## 实施顺序

1. 写 `tests/test_plan_revision.py` 夹具：证明 `completed_work` 丢失、约束可被静默改写、已完成步骤可被替换重跑。
2. 实现分级修订原语与不变量校验；违约修订被拒绝并记录原因，任务状态可解释。
3. 接线：`react/engine.py` 的连续失败恢复改走 append 原语（小补丁，交 runtime 线）；修订记录进 `change_reasons` 与审计事件。
4. 回归既有计划、ReAct、审批、取消、暂停恢复与工作流路径；确认无第二套计划权威。

## 验收

- 任何修订不得丢失或改写 `original_goal`、`immutable_constraints`、已完成步骤证据；`completed_work` 单调不减。
- 修订不得把已有副作用的步骤排成可重跑；`unknown` 强制对账，不伪装未执行。
- 修订后计划仍通过 `validate()`（完整性/依赖/验收条件），否则修订被拒绝且拒绝原因可追溯。
- 修订留记录（级别、原因、前后差异、时间），崩溃恢复后可读；续跑从账本与证据推断，不从计划文本推断。
- 混合节点与恢复步骤仍走同一执行网关，不因修订获得新权限。
