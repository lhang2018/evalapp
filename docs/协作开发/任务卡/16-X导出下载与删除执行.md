# ALN-16-X：导出下载与删除计划的实际执行

当前负责人：claude-main；状态：in_progress（2026-10-23 认领）。ALN-16 整包遗留项
（16-A/16-R 均已 accepted；台账 next_step 明示「实际导出下载与存储删除待接线」）。

## 目标

现状（源码依据）：`evoagent/observability/export.py` 已有 `plan_deletion` 产出
删除**计划**（event_ids + digest + 墓碑摘要），`core/log_layers.py` 已有
`delete_diagnostics_for_task` 等存储删除原语——但两者**没有接通**：计划生成后无
执行器，导出报告无落盘下载产物。本卡补齐两段执行链：

1. `execute_deletion(db, plan, *, actor, reason)`：按计划校验 digest 与范围后
   调用存储原语逐层删除，返回逐层计数与审计记录；范围外 task 拒绝执行；
   二次执行（幂等重放）按计划幂等（已删计数为 0 不算失败）；
2. `export_to_file(exporter, events, path, ...)`：导出报告写入文件（含清单摘要
   与 actor/reason 审计头），文件哈希入审计；路径必须落在授权根目录内
   （拒绝 symlink 逃逸）；
3. 墓碑与审计记录持久化（走 `Database` 具名方法，不造通用 execute）。

## 写入边界

可独占新增：`tests/test_export_deletion_exec.py`、本卡与交付文档。
可小改：`evoagent/observability/export.py`（新增执行函数，不改既有
`plan_deletion`/`EvidenceExporter` 语义）、`evoagent/core/log_layers.py`
（若需暴露按 task 的统一删除入口，只做加法）。
不修改：`evoagent/api/server.py`、`core/controller.py`、`core/events.py` 表结构、
Android 端。本卡不宣称 API 层已暴露端点，只交付可被调用方显式调用的执行器。

## 验收

1. 计划→执行→读回：删除后存储中该 task 事件/诊断/证据计数为 0，墓碑与审计
   可查（范围摘要与 actor/reason 完整）；
2. digest 不匹配或范围含其它 task → 拒绝执行且不删任何数据（fail-closed）；
3. 幂等：同计划重复执行第二次全部计数 0 且 ok；
4. 导出文件：内容与 `EvidenceExporter.export` 一致、含审计头、哈希入审计，
   路径逃逸（`../` 或 symlink）被拒；
5. 确定性：同输入同输出（复用既有 canonical_digest 口径）。
