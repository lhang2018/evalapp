# ALN-03-S：发布正文签名与完整兼容声明

建议角色：assets。前置 ALN-00 已具备候选基线；本卡先锁定服务端可验证的签名载荷与兼容声明，端侧公钥验签由 Android 线消费，不替代其验收。

## 目标

让发布清单不再只信调用方传入的 `signature_ok` 之类的布尔值：服务端按规范化字节重新计算制品摘要与签名，拒绝正文篡改、缺文件、错误摘要/签名/密钥；稳定通道的清单必须完整声明平台、最低 App、权限、工具、Schema、模型、离线与回滚信息。

## 写入边界

独占 `evoagent/release/signing.py`（新增签名载荷/验签模块）、`evoagent/release/manager.py` 的发布校验接线与 `tests/test_release_signing.py`。

`evoagent/release/delivery.py` 的端侧回执接线、客户端验签与真实制品下载装载属后续卡；`core/contracts.py`、共享持久化、路由与 App 装配由集成角色合入。不得把服务端签名秘密下发给客户端。

## 实施顺序

1. 定义规范化 signing payload：稳定字段排序/UTF-8/长度前缀，覆盖 manifest 身份、制品文件清单与逐文件摘要、渠道、发布者密钥标识与时间；写契约测试锁定字节。
2. 实现摘要重算与签名验证：制品字节来自实际文件清单，清单缺文件、多文件、摘要不符、签名不符、未知密钥标识均拒绝；签名算法与密钥来源可注入，便于测试与轮换。
3. 实现稳定通道兼容声明校验：平台/最低 App、权限、工具、Schema、模型档案、离线能力与回滚目标缺项即拒绝；草稿/内部通道可放宽但必须显式标记。
4. 在 `ReleaseManager` 的晋级/发布路径调用验证，持久化验证证据（载荷摘要、密钥 ID、结果、失败原因），拒绝行为可审计。
5. 为既有合法清单提供明确迁移策略（重新签名）或显式拒绝旧格式，不静默接受。

## 验收

- 正文被篡改、文件缺失/多余、摘要或签名错误、未知密钥标识均不能发布。
- 稳定通道缺任一兼容声明即拒绝，且错误信息指明缺项。
- 合法制品用真实文件字节验证通过，验证证据可按发布 ID 追溯。
- 旧格式行为明确：要么带证据迁移，要么拒绝，不得默认放行。
- 服务端只验证公开密钥/对称校验边界与端侧公钥信任设计分开记录。

## 交付

签名载荷规范与实现、兼容声明校验、发布路径接线、失败/迁移测试与证据；首轮不关闭真实制品下载/端侧装载（ALN-11）。

可复制给接手者：

> 认领 ALN-03-S。读本卡与正式版发布/更新卷，先锁定规范化签名载荷字节和兼容声明字段，再在 ReleaseManager 发布路径重算摘要并验签。独占 signing 模块与测试；共享契约、App 装配和端侧回执另行协调。用真实文件字节证明篡改/缺文件/错密钥被拒，不接受调用方布尔值。
