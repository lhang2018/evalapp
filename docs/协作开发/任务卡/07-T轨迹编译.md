## 目标

现状：`ExecutionPlan` 有步骤/依赖/修订留痕，但**没有轨迹编译层**——执行历史
（哪些步骤成功、输入绑定到哪个值、失败后有哪些可恢复分支）不能被重放或编译成
可分析的轨迹对象。本卡交付**纯读的轨迹编译器**：

1. 从 `ExecutionPlan` + 步骤状态编译执行轨迹：步骤序列、每步输入绑定引用
   （不内联大对象，只记来源）、状态与证据引用；
2. 失败/跳过步骤的**恢复分支候选抽取**：按依赖图找出可重试的候补路径
   （哪些步骤重跑即可、哪些需要先补依赖、哪些已不可能）；
3. 轨迹可序列化（`to_dict/from_dict` 往返），供崩溃恢复与评测消费。

## 验收

1. 轨迹编译覆盖全状态（pending/running/done/failed/skipped），已完成步骤的
   证据（completed_work、修订记录）原样进入轨迹；
2. 恢复分支候选按依赖可达性分类：`retryable`（仅自身失败，重跑即可）、
   `blocked`（依赖链上有未恢复失败）、`ready_after`（指明需先恢复哪些）；
3. 确定性：同一计划同一状态编译结果与遍历顺序无关；
4. 序列化往返保持全部字段；
5. 修订历史进入轨迹（级别/原因/增删），崩溃恢复可读取；
6. 夹具先证缺口：实现前「无轨迹编译器」即 import 失败。
