# ALN-00-B：发布可共享开发基线

建议角色：integration。负责人/审阅人/分支在 workboard.json 认领，不在本卡虚构人员。当前可立即开始整理；未完成前其他线不接入新的运行内核。

## 目标

把验证结果绑定到其他人能从 Git 取到的精确提交。ALN-04 已随 `72d20f0` 提交，ALN-10-Q/R 已随 `3713a9e`/`bd33f56` 提交；不得再以“ALN-04 未提交”阻塞准备工作。最新干净候选及证据见工作板 baseline.prepared_candidate，历史 baseline.snapshot 仅保留初始在途快照。

正式发布仍需独立审阅；本线作者不能自审自己的 ALN-04/10，真机和真实供应商验收也不能由本地测试替代。提交清单、干净副本验证和交接材料可先完成，准备完成不等于 baseline.status=published。

## 写入边界

本卡负责提交编排、基线记录和交接验证，不顺带重构业务。逐文件审阅运行/审批源码、新增测试、schema v2/v3、API/CLI、客户端及文档。未跟踪的新文件是依赖的一部分，不能只提交 git diff 中已跟踪的改动。

独立通知改动当前涉及 DevicePackage.kt、backgroundRunner.ts、NotificationModule.kt、nativeNotifications.ts、notifications.ts 及其测试。先确认实际归属和依赖，再决定独立提交/保留在途；不能整包吞入本卡，也不能直接删掉。未知 .workbuddy/ 不属于默认交接范围。

## 实施顺序

1. 读取当前 status、候选文件摘要和三份已交付记录；核对未归属差异。
2. 核对现有运行/审批、资产、模型及回归提交，整理提交清单和遗漏文件；不要重复提交已经进入 main 的代码。保留原始测试失败与最终通过证据。
3. 在独立干净工作树检验候选提交，确认所有 imports、schema、路由和客户端依赖齐全；不要拿原工作区隐式文件填补缺失。
4. 重跑全量与台账/映射检查，记录精确 commit、工具版本、命令、pass/fail/skip 与不同测试数量的原因。
5. 更新 workboard.json 的 baseline.status/published_commit，发布基线引用；各任务卡登记 base_commit 后进入实现。

## 验收

- 别人只取公布的 commit 和仓库声明的依赖，可以跑核心执行/问答/审批回归；不会引用未提交的文件。
- 源码、测试和提交对应；通知若未纳入，结果清单说明区别，不把候选工作区 671/132 写成提交快照结果。
- 无令牌、数据库、设备私有数据或未知目录混入；现有在途改动仍可恢复。
- baseline.status=published 时 published_commit 为真实完整提交标识，不能填写“当前工作区”。

## 交付

提交列表、快照验证报告、未纳入改动及负责人说明、更新后的认领表。不要把完成本卡解释为 ALN-01..04 全包已验收。

可复制给接手者：

> 认领 ALN-00-B，先阅读 docs/协作开发/README.md 和本任务卡。只整理并验证可共享源码基线，按差异归属分提交，保留其他人的通知等在途工作。用干净工作树验证候选 commit，填写 workboard.json 的真实基线和证据。不要将原工作区测试结果直接当作提交快照结果，也不要通过清理工作区消除未知改动。
