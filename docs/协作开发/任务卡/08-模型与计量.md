# ALN-08-M：路由覆盖复核与可对账的模型计量

建议角色：models。正式前置 ALN-00、ALN-01；可先复核已提交的 F-53 并准备独立夹具，完整运行接入等待基线与网关兼容确认。

## 目标

在已有模型注册/路由、routing_eval 和计量基础上补缺口。当前 HEAD 已含 F-53 等同期工作，不能按历史审查中“完全没有”重新开发。先确认意图、专家、工作流、执行模式、模型五层评测实际覆盖，再补真实用量和费用证据；未知费用不能按免费处理。

## 写入边界

主要维护 models/ 和 evolution/routing_eval.py、api/routing_eval_api.py 对应功能；新增独占计量/路由测试与夹具。memory/ 和观测治理属于后续 ALN-05/16，不与首卡混做大重构。

budget.py、core/contracts.py、事件字段、controller.py、共享持久化及 App/CLI 装配通过归属角色集中合入。不要绕过工具网关或让适配器接管任务状态。

## 实施顺序

1. 给当前五层决策列“已有实现/真实调用入口/测试/缺口”，标出 F-53 和最新代码能证明的范围。
2. 锁定路由报告与计量接口：固定数据集版本、基线/候选版本、回退原因、实际模型/提供方、调用关联和真实使用量来源。
3. 区分调用前预估、调用后实测、已知免费 Mock、缺失/未知费用；把预留/结算接口交 ALN-15 与 runtime 评审，不能直接新建并行费用权威。
4. 以确定性适配器夹具覆盖限流、超时、供应商错误、能力不足、低置信与费用缺失；有授权环境和凭据时再补真实提供方联调证据。
5. 报告追溯到实际执行模型和 Run/Manifest，评测流量继续隔离，不能反向触发自身进化。

## 验收

- 五层覆盖结论有实际入口和行为测试；缺失层明确标出，不用字段存在代替调用。
- 低置信进入可回答等待或安全回退；不兼容模型不因评分高而进入执行。
- 预估与实测可区分并对账，未知费用保留未知；账本/报告不重复计费。
- 限流/超时/回退有界，错误证据不泄露凭据；真实联调与 Mock 结论分开。
- 与现有 routing_eval、模型预算、运行清单及回归测试兼容。

## 交付

覆盖复核表、计量/预算消费接口、确定性故障夹具、修复实现及专项报告；未提供真实供应商证据时保留 ALN-08 相应验收缺口。

可复制给接手者：

> 认领 ALN-08-M。先复核当前 HEAD 已有的 F-53/routing_eval，不重复造轮子。产出五层路由覆盖证据和预估/实测/未知计量接口，再用确定性夹具实现缺失路径。独立适配器/路由代码可并行，预算、事件、持久化、运行控制接线由归属角色整合。真实计费缺失不能写成零费用，适配器不获得执行权。
