# ALN-06-A：统一不可变资产身份与最小消费接口

建议角色：assets。正式前置 ALN-00、ALN-03；当前 ALN-03 服务端校验已有首批交付，但整包仍有剩余。可先做契约/夹具与独立资产域，真实发布接入等对应接口与基线就绪后整合。

## 目标

给专家、工作流、模型档案、Skill/Pack 和评测资产提供可追踪的身份、内容摘要、依赖与生命周期。先补基础，不在同一卡里同时做真实漫剧、候选调度或 Android 安装器。

## 写入边界

独占拟新增 evoagent/assets/、资产域 schema、api/assets_api.py 和 tests/test_asset_identity.py。先检查现有专家/工作流库与能力目录可复用的实体，避免平行再造注册中心。

release/manager.py、delivery.py 属本线整合范围，但首轮仅提交必要生产端边界；core/contracts.py、共享持久化、路由/装配、Task Manifest 的接线由对应整合角色处理。Android 字节验签由 android 线负责。

## 实施顺序

1. 按正式契约明确 Asset 字段、八态、namespace 和不可变引用；写出与当前 Expert/Workflow/模型清单的映射，列兼容与缺失信息策略。
2. 定义生产/消费双方最小接口：登记、按精确版本读取、依赖解析、兼容检查、晋升/弃用、引用查询。消费者不能只拿可变的“最新版本”字符串执行。
3. 实现独立域仓储与内容规范化；同 ID/version 不允许覆盖内容，内容相同重复登记可按明确规则幂等。
4. 给 Skill/Capability Pack 定义可验证目录/字节清单、依赖/权限/评测/回滚引用；先用本地夹具验证装载协议，不伪称端侧已有真实装载。
5. 和 runtime 锁定 Manifest 资产引用，和 android 锁定字节格式、摘要及公钥身份；共享接线单列合入。

## 验收

- 同版本内容变化被拒绝；别名/最新指针不会改变已冻结运行实际读取的内容。
- 依赖缺失/环/不兼容、来源或评测证据不足，不能激活或晋升。
- 旧专家/工作流仍有可解释的精确版本映射；回滚引用能取到原内容。
- 依赖读取、晋升和安装/退役有可追溯证据；GC 不删除在用版本。
- 服务端 HMAC 校验与端侧公钥验签的责任分开，不能向客户端传服务端签名秘密替代信任设计。

## 交付

Asset 映射/接口、独立服务和迁移提案、不可变/依赖行为测试、Pack 字节夹具、runtime/Android 接入补丁。首轮基础验收不自动关闭整个 ALN-06，更不关闭 ALN-09/11。

可复制给接手者：

> 认领 ALN-06-A。读本卡与正式 Asset 契约，先核对现有专家/工作流/能力目录，产出统一资产身份和最小消费接口，再实现不可变内容与依赖校验。独占资产域和测试；共享契约、持久化、运行清单与客户端接入提交小补丁协调合入。用真实文件字节夹具证明版本不可变，不把元数据槽位当能力装载完成。
