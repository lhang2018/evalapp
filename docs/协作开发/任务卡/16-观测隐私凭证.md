# ALN-16-A：观测证据、隐私与凭证治理

建议角色：安全/可观测。本卡先建立跨端事件/隐私/故障等级契约与决策链重建能力，再补最小化导出/删除、外部内容不可信来源保留和凭证分级/轮换；不重写既有四层日志存储，只在边界处统一口径。

## 目标

同一 task/run/effect/approval 能跨事件、审计、诊断、评测与发布重建完整决策链；跨角色/范围读取受策略约束；外部注入内容保留不可信来源且不扩大权限；诊断/日志/导出最小化脱敏；API 令牌与发布签名密钥分级、可轮换、可解释撤销，且密钥材料永不进入模型上下文、导出或日志。

## 写入边界

新增 `evoagent/observability/`（跨端契约、决策链、导出/脱敏、凭证治理）与 `tests/test_observability_evidence.py`；只对 `core/privacy.py`、`core/events.py`、`api/auth.py` 做向后兼容的增量接线，不改四层存储表语义。

共享台账、`core/contracts.py`、持久化迁移与 App 装配由集成角色合入；并行会话在途文件不得触碰。

## 实施顺序

1. 定义统一契约：来源（device/server）、信任（trusted/untrusted）、隐私四值（public/internal/sensitive/restricted）、故障等级（none/transient/degraded/fatal）、以及 task/run/node_run/effect/approval/candidate/release 引用字段；提供 `RunEvent` 适配与校验。
2. 实现决策链：按引用聚合并按因果/序号排序，输出节点、边、缺失引用与证据摘要；支持按 task/run/effect/approval 反查，不把原始日志直接当结论。
3. 实现外部内容来源保留：包装外部文本（网页/文件/工具返回/诊断包），标记 origin/trust，脱敏与导出时不得升级为 trusted，也不得凭内容扩大授权。
4. 实现最小化导出/删除：按角色与隐私等级过滤，密钥/令牌模式强制抹除，导出附清单摘要与 actor/reason 审计；删除按 task/scope 级联并保留审计墓碑。
5. 凭证治理：API 令牌环与发布签名密钥分层（服务端签名/设备签名/客户端信任），支持新增、轮换、撤销与旧密钥验证窗口；提供可解释状态与禁止导出/入上下文检查。

## 验收

- 同 task/run/effect/approval 可重建决策链，缺失引用显式报告而非静默补全。
- operator 无法读取 admin 专属层或跨任务证据；导出仅含授权且最小化字段。
- 注入内容标记为 untrusted，不能借内容获得新工具/范围/审批。
- 密钥/令牌不会出现在导出、日志摘要或模型上下文样例中。
- 轮换后新密钥可通过、旧密钥在保留期内可验、撤销后拒绝，状态可解释。

## 交付

统一契约、决策链、导出/删除、凭证治理模块与专项测试；正式部署鉴权接线、密钥托管与跨端全链联调列为未完成项，不关闭整包 ALN-16。

可复制给接手者：

> 认领 ALN-16-A。读本卡与 09/18 卷观测与安全章节，先定跨端事件/隐私/故障契约和引用字段，再实现决策链重建、外部内容不可信标记、最小化导出/删除与凭证分级轮换。新增 observability 模块与专项测试；core 与 auth 只做向后兼容增量。用跨角色越权、注入内容、密钥泄漏样例证明边界。
