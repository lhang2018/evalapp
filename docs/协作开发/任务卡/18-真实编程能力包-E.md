# ALN-18-E：统一 diff 输入与原子应用

建议角色：runtime。承接 ALN-18-C/D：`coding_patch` 已支持 `{path, old_text, new_text}` 原子提交、事务日志与恢复，但模型/工具常直接产出标准 unified diff，目前必须手工拆成 old/new 文本。

## 目标

- `coding_patch` 新增可选输入 `diff`（字符串），与 `edits` 二选一；`diff` 解析为标准 unified diff：
  - 支持 `---`/`+++` 文件头、`@@ -a,b +c,d @@` 多个 hunk、多文件、`a/`/`b/` 前缀。
  - 同一文件的多个 hunk 按顺序应用，最终合并为**一条** prepared 记录，沿用现有预检、写后核验、事务日志与回滚。
  - hunk 上下文块必须在当前文件中唯一命中；未命中或多处命中即整体拒绝、不写盘。
  - 明确拒绝：`/dev/null`（新增/删除文件）、`\ No newline at end of file`、非法 hunk 头、`edits` 与 `diff` 同时提供或都不提供。
- `dry_run`、`expected_sha256`（`edits` 模式）、语法门禁、日志与恢复行为保持不变。
- 证据仍逐文件给出 `file`、行号（首 hunk 起始）、完整 `sha256_before/after`。

## 写入边界

可独占修改：

- `evoagent/tools/coding.py`
- `tests/test_coding_tools.py`
- `docs/协作开发/交付/ALN-18-E-*.md`

不得触碰：注册表、`contract.py`、`app.py`、专家注册表及执行路径共享文件。本卡不接线。

## 验收

- 两文件、各含一个 hunk 的 diff 原子应用成功，逐文件证据完整。
- 同一文件两个 hunk 的 diff 应用成功，结果与逐条 old/new 编辑一致。
- 任一 hunk 上下文未命中或多处命中 → 全部不写盘；非法头部/`/dev/null`/无换行标记 → 明确拒绝。
- `edits` 与 `diff` 互斥校验生效；`diff` 模式下 `dry_run` 返回统一 diff 且不写盘。
- 能力包版本升到 `1.4.0`，`rollback_version=1.3.0`，工具 ID 仍为八个。
- 既有 30 项测试不回归；新增专测覆盖上述解析与拒绝路径。
