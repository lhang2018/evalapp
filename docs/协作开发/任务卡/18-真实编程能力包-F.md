# ALN-18-F：新增/删除文件与 hunk 位置容错

建议角色：runtime。承接 ALN-18-E：统一 diff 已可原子应用，但明确拒绝 `/dev/null`，且 hunk 只按内容唯一命中定位——重复片段无法消歧，上下文略有漂移（如文件顶部/底部插入过行）就整体失败。

## 目标

- `diff` 解析支持 `/dev/null`：
  - `--- /dev/null` + `+++ b/<path>` → 新增文件；hunk 只允许新增/上下文行，旧计数必须为 0。
  - `--- a/<path>` + `+++ /dev/null` → 删除文件；hunk 只允许删除/上下文行，新计数必须为 0。
  - 两侧同为 `/dev/null`、创建目标已存在、删除后仍有剩余内容 → 明确拒绝，不写盘。
- hunk 定位容错（仅 `diff` 模式）：
  - 内容唯一命中 → 直接应用。
  - 多处命中 → 用 hunk 头旧起始行号（叠加同文件已应用 hunk 的行数偏移）消歧；仍不唯一则拒绝。
  - 零命中 → 逐层裁掉首/尾成对的上下文行（最多 2 行）后重试；裁剪后必须唯一命中，否则拒绝。
- 新增/删除与改写同批原子执行：任一失败全量回滚——新建的文件删除、删除的文件按原文恢复、改写的文件恢复原文。
- 事务日志与恢复覆盖创建/删除：日志记录 `existed`/`deleted`；恢复时创建文件应被移除、删除文件应被还原，冲突不覆盖。
- `edits` 模式、`dry_run`、`expected_sha256`、语法门禁、写后核验行为保持不变；`dry_run` 预览新增/删除文件时使用 `/dev/null` 侧。
- 证据逐文件给出 `file`、`line`、`action`（`created`/`deleted`/`modified`）、完整 `sha256_before/after`（不存在一侧为空串）。
- 能力包升到 `1.5.0`，`rollback_version=1.4.0`，工具 ID 仍为八个。

## 验收

- 新增文件：`/dev/null` → 新文件的 diff 原子创建成功，父目录不存在时明确拒绝。
- 删除文件：完整移除内容的 diff 原子删除成功；内容未被完全覆盖时拒绝且文件不变。
- 创建目标已存在、两侧 `/dev/null`、创建 hunk 含删除行、删除 hunk 含新增行 → 明确拒绝。
- 重复片段：多命中时按行号命中正确位置；行号不符则拒绝。
- 上下文漂移：首/尾各多一行过期上下文（不超过 2 行）时可裁剪后唯一命中；超过 2 行或裁剪后仍歧义则拒绝。
- 混合补丁（改写 + 新建 + 删除）原子成功；任一写盘失败时新建文件被删除、删除文件被恢复、改写文件复原。
- 日志恢复：pending 日志中的新建文件被移除、删除文件被还原；内容已偏离则冲突且不覆盖。
- 既有 37 项测试不回归；新增专测覆盖上述路径。
- 能力包版本 `1.5.0`，`rollback_version=1.4.0`，工具 ID 八个。
