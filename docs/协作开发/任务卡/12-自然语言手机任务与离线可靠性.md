# ALN-12-A：自然语言任务—设备执行/回执协议与离线故障矩阵

当前负责人：codex-runtime，串行排队未开工。依赖 ALN-01-A（统一授权，review）、ALN-02-A（回执对账，review）、ALN-04-R（运行接管，accepted）已交付接口；本卡只消费这些接口，不替它们做验收结论。通知/后台runner有历史未提交修改；当前虽仅一个开发会话，仍先核对差异和依赖，独立处理，不直接覆盖或计入本卡已交付范围。

## 目标

现状：`android-app/src/device/broker.ts` 已有风险分级、独立确认、动作日志与未知副作用禁止重放，但 `DeviceAction`/`ActionJournalEntry` 没有 `task_id`/`run_id`/`effect_id` 关联（`android-app/src/device/types.ts`）；`offline/tasks.ts` 只有本地/服务端任务映射，未把自然语言任务接到设备动作；服务端/模型/网络/同步故障的降级矩阵尚无单一权威。结果：任务链路无法从 task 追到 effect，也无法证明断网/重启后动作与事件一致。

本卡交付：统一的「自然语言任务 → 设备动作提议 → 审批 → 执行/观察回执」契约、task/run/effect 引用规则、服务端/模型/网络/同步故障降级矩阵，以及先用夹具证明现状缺口的测试。首份交付只定协议与矩阵，接线按后续小卡推进。

## 写入边界

可独占新增：`android-app/src/device/taskProtocol.ts`（提议/回执/引用契约）、`android-app/src/device/failureMatrix.ts`（故障分级与降级规则）、`android-app/test/device/taskProtocol.test.ts`、`android-app/test/device/failureMatrix.test.ts`、本卡交付文档。

可在本卡内小改：`android-app/src/device/broker.ts`、`android-app/src/device/types.ts`（只加可选关联字段与回执投影，不改既有风险/幂等语义）。

本卡不改历史未提交的 `android-app/src/device/notifications.ts`、`android-app/src/device/nativeNotifications.ts`、`android-app/android/app/src/main/java/com/evoagent/NotificationModule.kt`、`android-app/test/device/notifications.test.ts`、`android-app/src/offline/backgroundRunner.ts`；先核对再独立处理，不能因当前单会话就混入本卡。`evoagent/api/server.py`、`evoagent/core/*` 属共享文件，本卡先交接口需求，实际接线须另行登记范围。

## 验收

- 提议契约含 `task_id`、`run_id`、`action_id`、`effect_id`、目标应用/路径、风险、预期观察；回执含终态、证据、时间戳，并能映射到 broker 的 `JournalState`。
- 同一 `task_id` 下重放同一 `action_id` 返回原结果、不重复下发；未知副作用不自动重放。
- 故障矩阵至少覆盖：服务端不可达、模型超时/限流、网络切换/断网、同步冲突、进程被杀、重启、低电量/低空间、无障碍服务未授权；每项写明降级动作、重试/停止条件、对账方式与用户可见状态。
- 敏感内容默认不进入上传载荷；矩阵与契约列明本地保留字段。
- 夹具先证明现状缺口（任务未关联设备动作、无统一 effect 引用、矩阵缺项），实现后同一夹具转绿。
