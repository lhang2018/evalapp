## 目标

当前 Android 已能回答问题并显示待审批编号，API 客户端有管理员详情/决策方法，但没有完整管理员审批页面。补齐“看清完整动作 → 批准/拒绝 → 跟踪结果”的交互，不重做服务端审批机。

## 已有协议

- Task.waiting_approvals 为审批 ID 列表；当前任务用 SUSPENDED 表示待审批，不能将其当业务失败。
- GET /approvals/{approval_id} 返回 action_summary、完整 binding_json、action_digest、expires_at、status 等；仅 admin 可读。
- POST /approvals/{approval_id}/decision 的正文为 {"approved":true/false}。新决策 202，同向重试 200；400 格式、403 角色、404 不存在、409 过期/冲突/非当前等待。
- 202 代表接受决策，未承诺已执行成功；继续查询 Task 和审批详情。ReAct/DAG 由服务端恢复原动作。
- EvoAgentClient.getApproval / decideApproval 已支持显式管理员凭据，不能把该凭据缓存到普通请求或同步事件。

## 写入边界

独占拟新增 android-app/src/features/approvals/ 下的页面、状态逻辑和测试。App.tsx、api.ts、offline/types.ts 由本线统一接线，避免多人同时修改单体 App。

通知、后台任务和原生 DevicePackage/NotificationModule 有独立未提交改动；先确认归属，不借本卡覆盖或重写。没有必要时不改原生桥、后台同步或更新装载器。

## 验收

- 完整显示实际参数、操作/目标、任务/节点/版本范围、当前状态和有效期，不能仅用被截断的 action_summary 让人批准。
- 区分普通操作者与管理员；无权限、过期、撤销、已消费、409 冲突均可解释并刷新，按钮状态由当前服务端状态决定。
- 批准/拒绝不会自动生成另一任务或替换参数；重复点击/网络重试遵循同一审批 ID 的幂等语义。
- 批准后继续跟踪原任务，拒绝显示取消；并行多个待批 ID 可逐项处理，部分批准不伪称全部执行成功。
- 错误、日志、本地同步、语音/通知与普通 API 请求不泄露管理员凭据。
- 离线保留可审阅信息和状态，不将离线点击当作已获服务端批准；恢复网络后按最新状态提交。
- 组件/状态测试与 typecheck 通过；最终补真机成功、拒绝、断网重试和过期路径证据。仅单元测试通过不能关闭真机验收。
