# ALN-18-A：真实编程能力包（定位 → 改写 → 验证）

建议角色：runtime。对应 C-12 与 WP-4.1：编程能力包必须有项目级符号定位、受约束改写、可执行的静态检查与测试验证，并以真实证据判定成功，而不是模型自述成功。

## 目标

当前 `evoagent/tools/` 只有通用文件读写与只读 git：没有 AST/符号定位，`file_write` 不做语法校验，也没有类型检查/测试执行适配器；`evoagent/experts/builtin.py` 的 `coding` 专家只是提示词与白名单，缺少真实编程工具支撑。

本卡交付**第一个可验证切片**：以项目根为边界的编程工具包，串起「符号定位 → 精确改写 → 静态检查 / 测试执行 → 证据」闭环。改写导致语法错误时必须拒绝写盘（或写后失败回滚），检查/测试非零退出绝不得判为成功。

## 写入边界

可独占新增：

- `evoagent/tools/coding.py`（工具包实现与能力包清单）
- `tests/test_coding_tools.py`
- `docs/协作开发/交付/ALN-18-A-*.md`

不得触碰：

- `evoagent/tools/registry.py`、`evoagent/experts/registry.py`（共享注册表，风险推导与执行生命周期的唯一权威）
- `evoagent/app.py`、`evoagent/core/controller.py`、`evoagent/react/engine.py`、`evoagent/tools/contract.py`（集成/运行在途共享文件）

本卡不在 App 启动路径注册新工具、不改 coding 专家的运行时白名单；接线到 `app.py`/`experts/builtin.py` 需串行交接，另卡或显式 shared 声明。能力包清单可在本模块内自描述并由测试直接安装到独立 `ToolRegistry` 验证。

## 验收

- 五个工具契约显式声明 `permission_requirements`、`side_effect_level`、`risk_class`、`offline_capable=True`/`requires_network=False`、`cost_model`、`contract_test_ref`；全部无网络访问。
- `coding_symbols`：项目根约束，跳过 `.git`/`node_modules`/`__pycache__` 等目录，返回定义/类/函数的 `file:line` 与限定名；语法错误文件单独列出，不静默跳过。
- `coding_edit`：路径越界、旧文本不存在或命中不唯一一律拒绝且不写盘；`.py` 改写后语法不合法必须拒绝写盘；写后重读比对，不一致则回滚并报告 `side_effect_uncertain` 依据。
- `coding_syntax_check`：真实子进程执行，非零退出 → `goal_reached=False`、`independently_verified=False`；不向项目目录写 `.pyc`（`PYTHONPYCACHEPREFIX` 指向临时目录）。
- `coding_typecheck`：类型检查器不可用时返回「不可用」而非成功（`goal_reached=None`、`executed=False`）；可执行时以退出码判定，测试用假检查器覆盖通过与失败两路。
- `coding_test`：真实 `pytest` 子进程，通过/失败/未收集三态可区分；未收集（rc=5）不得判成功；超时归类 `timeout`。
- 能力包清单声明 `pack_id`/`version`/`tool_ids`/`rollback_version`/`contract_test_ref`；升级以版本清单表达，回滚目标显式声明（模块级实装回滚接线待注册表提供卸载语义，记录为下一卡）。
- 证据可追溯：每个结果含 `evidence`（文件、行号、摘要、退出码、耗时、输出尾部）。
- 负向专测：语法坏代码、失败测试、错误路径都不得被判成功。
