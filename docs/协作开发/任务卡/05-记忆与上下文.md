# ALN-05-M：多维记忆、ContextManifest 与冲突/删除

建议角色：models。前置 ALN-00/ALN-04 已具备运行身份与上下文装配；本卡先打通身份隔离与可追溯装配，再把冲突裁决与删除传播接到同一来源链。

## 目标

让用户、项目、会话、任务、专家五类身份在记忆读写与上下文装配中真正隔离；每次装配产出不可变 ContextManifest，记录来源、版本、预算与压缩选择；冲突不静默覆盖，删除源记忆后派生摘要不可继续检索。

## 写入边界

独占 `evoagent/memory/manifest.py`（新增 ContextManifest）、`evoagent/memory/conflicts.py`（新增冲突/失效链）、`evoagent/memory/store.py`/`context.py` 的必要接线，以及 `tests/test_memory_manifest.py`、`tests/test_memory_conflicts.py`。

`core/task.py` 的身份字段、共享持久化、schema 迁移与 controller 装配由集成角色合入；不得另造平行记忆库或把身份塞进自由文本标签。

## 实施顺序

1. 明确身份模型：user/project/session/task/expert 的作用域键与继承关系，定义跨作用域检索的显式授权，写入时记录来源与作用域；用测试证明不同用户/项目/会话/专家互不串数据。
2. 每次上下文装配生成不可变 ContextManifest：条目 ID、来源、版本/时间、被选原因、token 预算、压缩前后引用、装配参数摘要；同一输入重复装配可复现同一 Manifest 摘要。
3. 冲突发现与裁决：同一事实键的新旧值、来源可信度与时间产生冲突记录；规则裁决（显式偏好优先、高可信来源优先）与人工裁决入口分离，冲突未裁决时不得静默覆盖，检索可标记“有冲突”。
4. 删除与失效传播：删除源记忆写入墓碑并沿派生摘要/缓存引用链失效；删除后原条目与派生摘要均不可检索，ContextManifest 保留当时的引用但不泄露正文。
5. 压缩边界：硬约束与验收条件在压缩后仍保留；领域策略与共享压缩共用同一来源链，不因压缩丢失可追溯性。

## 验收

- 跨用户/项目/会话/专家不串数据，越权检索被拒绝而不是静默空结果。
- 每条被装配上下文都能追溯到原始记忆 ID、来源、版本与选择原因。
- 冲突不会静默覆盖；未裁决冲突在检索与 Manifest 中可见。
- 删除源记忆后派生摘要/缓存不可继续检索，且墓碑可审计。
- 硬约束与验收在压缩后保留；ContextManifest 摘要可复现。

## 交付

身份/作用域契约、ContextManifest 实现、冲突与删除传播、装配接线与回归测试；首轮不关闭 ALN-12 的端侧离线记忆与 ALN-16 的隐私治理整包。

可复制给接手者：

> 认领 ALN-05-M。读本卡与正式版记忆卷，先定五类身份作用域与 ContextManifest 字段，再实现可追溯装配、冲突裁决与删除传播。独占 memory 新模块与测试；Task 身份字段、持久化和 controller 装配提交小补丁协调。用测试证明不串数据、冲突不静默覆盖、删除后派生摘要不可检索、压缩保留硬约束。
