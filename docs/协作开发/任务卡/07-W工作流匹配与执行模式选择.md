# ALN-07-W：工作流匹配与执行模式选择

当前负责人：claude-main；状态：in_progress（2026-10-23 认领）。关联 ALN-07 整包第一项「工作流匹配」，
与 ALN-07-P（计划修订，已交付待独立复核）互补，不改其分级修订语义。

## 目标

现状（源码依据）：

- `evoagent/planning/planner.py` 只按意图产出步骤，**没有任何工作流匹配层，也没有执行模式概念**——
  官方设计《总体架构》§6 明确三种执行模式（稳定工作流 / 混合 Agent 工作流 / 动态规划）与
  「稳定工作流先检查输入、权限、依赖、版本和预算」；
- R-03「路由质量评测与纠错」的正式主题是「评估专家选择、**工作流匹配**、**执行模式**和模型选择」，
  但已落地的 F-53 只评测意图与专家，**台账写 ✅ 早于实际覆盖**——工作流匹配与执行模式两项既无实现也无评测；
- 现状报告第 3/4 节把「一次真实任务能证明用哪个身份、哪版资产、为什么选这条路径、真正执行了什么」
  列为 ALN-07 的剩余差距，其中「为什么选这条路径」正缺这一层。

本卡交付**显式的工作流匹配与执行模式选择**：候选工作流按五项检查判定适用性，模式显式选择并留痕理由，
并把这两个维度补进路由评测，使 R-03 的判定与实际一致。

## 写入边界

可独占新增：`evoagent/planning/matching.py`（匹配与模式选择）、`evoagent/planning/contracts.py`
（候选/模式/理由的数据契约）、`tests/test_workflow_matching.py`、本卡交付文档与设计契约。

可小改：`evoagent/planning/planner.py`（计划记录所选模式与理由，不改既有分级修订与步骤生成语义）、
`evoagent/evolution/routing_eval.py`（补工作流/模式评测维度，保留既有指标口径）。

不修改：`evoagent/core/controller.py`、`evoagent/react/engine.py`、`evoagent/core/runtime_budget.py`、
`evoagent/goals/`、Android 端与 `evoagent/api/server.py`——这些是并行会话在途或已被其它卡占用。
本卡不宣布运行时已接入匹配层，只交付可被调用方显式调用的服务与评测。

## 验收

1. **五项检查**：稳定工作流候选必须同时满足输入、权限、依赖、版本、预算五项；任一不满足即拒绝，
   且拒绝原因可查（缺哪个输入/哪项权限/哪个依赖/哪个版本/超多少预算），不得静默降级。
2. **模式显式**：三模式中必须选出其一并留痕理由；无适用稳定工作流 → 动态规划；部分匹配 →
   混合 Agent 工作流（列出需动态判断的节点）。不允许「隐式默认」。
3. **确定性**：同一候选集与输入的匹配结果与顺序无关（候选顺序、输入顺序都不改变选择与理由）。
4. **预算不越权**：匹配阶段的预算检查只读已声明额度，不得在匹配阶段实际扣账。
5. **评测覆盖**：路由评测集新增工作流匹配与执行模式两个维度，能给出各自准确率；R-03 的台账判定
   与实际覆盖一致（覆盖不足则降级，覆盖到位再恢复）。
6. **夹具先证缺口**：同一夹具在实现前暴露「无匹配层/无模式字段」，实现后转绿。

## 实施顺序与完成边界

1. 先定候选工作流与模式的契约（字段、枚举、理由结构），写设计与任务卡；
2. 实现匹配与选择服务（纯函数 + 显式输入输出，不引入第二套授权/预算权威）；
3. 接入 planner：计划对象记录 `execution_mode` 与 `selection_rationale`，不改变既有步骤生成；
4. 补评测维度与回归；按 §验收 逐条留证；交独立复核，作者不自批；
5. 真实运行时接线（由调用方显式调用匹配服务）属后续范围，本卡不宣称主链已自动匹配。
