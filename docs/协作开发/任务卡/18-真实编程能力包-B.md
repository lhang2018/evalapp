# ALN-18-B：跨文件引用/调用图与并发安全改写

建议角色：runtime。承接 ALN-18-A（`acbd22a`）第一切片：定位只覆盖定义，改写没有并发保护。本卡补齐「改哪里、谁在用、改之前值没变」三个证据点。

## 目标

现状：`coding_symbols` 只返回定义与导入集合，无法回答「这个符号在哪些文件被调用」；`coding_edit` 只校验旧文本，若文件在模型读取后被其他会话修改，仍会按旧内容改写。并行工作流共享同一工作区，这个窗口是真实的。

本卡交付：

- `coding_references`：按符号名给出定义、导入边、同文件/跨文件使用点与调用点，并标注置信度（类型未解析的静态启发式，不冒充 LSP 精度）。
- `coding_edit` 新增 `expected_sha256` 乐观并发保护：与当前文件摘要不一致时拒绝写盘。
- 符号结果补充函数签名/返回注解，便于精确改写。
- 能力包版本升到 `1.1.0`，`rollback_version=1.0.0`，新增工具纳入清单。

## 写入边界

可独占修改：

- `evoagent/tools/coding.py`
- `tests/test_coding_tools.py`
- `docs/协作开发/交付/ALN-18-B-*.md`

不得触碰：`evoagent/tools/registry.py`、`evoagent/experts/registry.py`、`evoagent/app.py`、`evoagent/tools/contract.py` 及任何执行路径共享文件。本卡不做专家/App 接线，不实现注册表级卸载（包级回滚仍以清单声明）。

## 验收

- `coding_references` 返回定义位置、使用点 `file:line`、调用点标记与置信度；同文件与已导入模块内为高/中置信，未导入文件的同名符号标低置信，不混为一谈。
- 引用分析同样受项目根与目录跳过规则约束；语法错误文件单列。
- `coding_edit` 带 `expected_sha256` 且文件已变化时拒绝写盘并报告期望/实际摘要；摘要匹配时正常改写。
- 改写证据输出完整 `sha256_before/after`，可作为下一次并发保护输入。
- 能力包清单版本 `1.1.0`、`rollback_version=1.0.0`、六个工具 ID；旧测试同步更新，负向测试不得放宽。
- 全量测试与台账校验保持通过。
