# ALN-07-R：可执行恢复策略（_risks_for 结构化）

当前负责人：claude-main；状态：review（原交付dfcfcee；2026-10-24审核修复f633130待独立复核）。ALN-07 整包第二项
（WP-6.4 剩余，07-P 交付文档明示的遗留项）。

## 目标

现状：`PlanningEngine._risks_for(intent)` 返回**静态中文文案**（如「涉及本地/设备
副作用，需权限确认」），计划消费者无法据此执行任何动作。本卡把风险声明升级为
**结构化、可执行的恢复策略**：

1. `RecoveryPolicy` 数据契约：风险类别（副作用需确认/高成本需局部重试/外部依赖
   不稳定）、建议动作（`require_approval` / `partial_retry` / `checkpoint` /
   `fallback_tool`）、适用条件与参数；
2. `_risks_for` 改为产出 `List[RecoveryPolicy]`，同时保留兼容读法
   （`plan.risks` 仍是字符串列表，从结构化策略渲染）；
3. `ExecutionPlan` 增加 `recovery_policies` 字段（可选、旧计划按空兼容）；
4. 提供 `recovery_for_failure(plan, step_id)` 纯读查询：给定失败步骤返回适用的
   恢复策略与依据，供引擎/评测显式消费。

## 写入边界

可独占新增：`tests/test_recovery_policy.py`、本卡与交付文档。
可小改：`evoagent/planning/planner.py`（新增契约与字段，不改修订分级语义与
步骤生成路径）。
不修改：controller/engine/side_effects/goals/Android。本卡不宣布运行时已自动
执行恢复，只交付策略声明与查询入口。

## 验收

1. 已知意图（note_taking/mobile_operation/comic_drama/general）产出的策略类别
   与原静态文案语义一致（文案由策略渲染而来，不再两处维护）；
2. 未知意图返回空策略列表，不隐式默认；
3. `recovery_for_failure` 只对失败步骤返回策略，done 步骤返回空（不重放成功副作用）；
4. 序列化往返保持；旧计划（无该字段）读取兼容；
5. 确定性：同输入同输出。
