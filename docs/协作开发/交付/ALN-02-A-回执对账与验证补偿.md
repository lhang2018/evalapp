# ALN-02-A 回执对账与验证补偿

负责人codex-runtime，接续ALN-01共用执行网关；用户要求完成两包剩余实现。

## 行为变化

1. planned意图与完整参数/工具版本在同一SQLite事务落库，再发布submitted并进入runner。参数或版本不符不能复用操作键；错误、超时和落库失败保持可查询的状态。状态转移使用当前态CAS，避免并发对账覆盖已决状态。
2. effect_receipts保存原参数、版本、结构化结果和独立核验收据。ToolContract.reconcile(operation, receipt)由供应商适配器读取真实状态并返回ToolResult；原版本不符、未独立验证、缺收据引用或结果未知均不释放pending。
3. 核验通过后，实际结果缓存、收据和账本裁决在同一事务提交。confirmed恢复实际产物，重启/续跑复用已确认结果，不重复执行或消费第二份动作审批。failed只接受独立确认未执行的结果，才允许原逻辑操作的新尝试。
4. 同进程内跨注册表追踪原调用线程；仍在执行时拒绝对账为安全重试。超时发生在最终检查等待阶段也保留unknown。进程退出后仍按真实回执裁决，线程超时不冒充已取消。
5. 同任务副作用批次串行执行，出现unknown即停止后续节点；纯计算批次继续并行。同优先级节点按定义顺序稳定调度，消除哈希种子差异。DAG保存原ToolResult并带入检查点/续跑，保留submitted/executed/uncertainty与产物。unknown立即waiting_external，不重试/不补偿；已执行但节点输出不合格不重复执行。结构化返回包含safe_to_repeat、retryable、required_action。
6. 补偿按依赖完成节点的逆序执行，参数来自当前任务原操作的持久记录，结果来自原操作真实输出；补偿也经过权限、范围、审批、预算和预记账。必须调用独立只读验证工具确认外部状态恢复，才把原操作标compensated；失败不伪装回滚成功。补偿未知/待审批保持等待并可续跑；验证预算耗尽保持暂停，不能宣称回滚成功。

## 接口与声明

GET /effects/{effect_id} 与 POST /effects/{effect_id}/reconcile 均需admin。POST携带receipt，客户端不能仅提交“confirmed”字样来改变状态；必须通过该工具版本的核验适配器。未注册适配器则明确拒绝。已配置的生产供应商应提供对应回执读取逻辑；本轮验收使用真实本地HTTP服务与真实文件，不代表已配置任意外部供应商。

补偿定义示例（工具必须在任务/专家授权内）：

```json
{"write":{"tool":"restore","args":{"path":"$args.path","content":"$output.previous"},"verify_tool":"verify","verify_args":{"path":"$args.path","expected":"$output.previous"}}}
```

$args为原动作持久参数，$output为持久原结果；$ctx/$nodes供显式依赖绑定。裸工具名旧格式不再被当作完整恢复策略，需迁移为带参数和独立验证的声明。内置漫剧移除了以fs_list列目录冒充视频回滚的配置。

原SideEffectLedger.reconcile仍保留为可信本地调用者的人工裁决兼容接口；管理员HTTP入口使用可验证回执路径。没有可靠结果的旧记录不能凭状态字样恢复产物，需可信对账或重建适配。
