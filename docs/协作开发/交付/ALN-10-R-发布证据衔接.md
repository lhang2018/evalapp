# ALN-10-R 发布证据衔接

本次接续用户“继续下一步”，在 ALN-10-Q 之上补齐发布入口对评测结论的实际消费；子卡独立跟踪，整包仍 partial_verified。

## 行为变化

评测完成后保存完整报告，在候选中记录唯一 report_id 与 SHA256；内容含候选声明/结果及评测集、保留集、阈值摘要。持久化失败不产生可发布凭据。恢复评测先清除旧结论和批准；评测或判定期间改变输入会拒绝。

approve 复核报告后，绑定相同报告/候选摘要和 approver。L2/L3 的 auto、空白批准被拒绝；L4/未知风险不允许普通批准。

HTTP 批准返回实际 ok/error，审计按结论记录 ok/blocked，拒绝不再被记录成成功。

deploy_candidate 必须读取该份持久化报告，校验摘要、候选、上下文、最新资产影响范围与独立门禁，再校验批准、当前稳定基线和可验证回滚制品。gate_passed=True 仅保留兼容参数，不能替代门禁；False 可以额外否决。发布签名清单包含报告 ID、摘要、完整证据与批准记录。底层发布失败保留 RELEASE_READY，重复成功调用因状态改变而拒绝。

## 接口与兼容

- EvolutionCandidate 新增 evaluation_report_id/evaluation_report_digest/approval_result；JSON 增量字段，旧候选可读但没有凭据时需新建/重评候选后批准。
- Database.get_eval_report(report_id) 精确读取，不受 list_eval_reports 默认50条影响，不增加表或迁移。
- baseline_version 与 rollback_version 在本发布入口必须是 ReleaseManager 当前精确 release_id；描述性版本串不能冒充当前稳定制品。
- L0/L1 仍允许 auto，但必须完成相同证据链。L2/L3 需具名批准与发布；API/CLI 的返回对象有明确 ok/error。
