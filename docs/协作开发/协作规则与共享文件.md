# 协作规则与共享文件

## 角色与文件归属

下表是共享文件的推荐整合职责，具体人员由认领表登记。其他开发线可以提出修改及小补丁，不能把整文件复制覆盖当作合并。归属不改变代码审查和业务授权要求。

| 共享文件 | 整合角色 | 协作方式 |
|---|---|---|
| evoagent/core/controller.py、runs.py、task.py、state_machine.py | runtime | 运行线维护 Task/Run 权威；其他线通过约定接口注入，不复制第二套编排器 |
| evoagent/react/engine.py、workflows/engine.py、tools/registry.py、core/permissions.py、approvals.py、side_effects.py | runtime | 执行动作、审批、允许列表和账本共用入口；补丁集中回归后合入 |
| evoagent/core/persistence.py、core/schema/migrations.py | integration | 域仓储独立实现；共享原子事务与既有表迁移由集成人统一接线、分配版本 |
| evoagent/core/contracts.py、events.py、budget.py、tools/contract.py | integration | 契约提案先定字段语义、取值、空值、兼容、错误与测试；消费者评审后一次落地 |
| evoagent/api/server.py、routes.py、auth.py、evoagent/app.py、cli.py | integration | 新功能用域路由/服务；导入登记、鉴权入口与装配统一合入 |
| android-app/App.tsx、src/api.ts、src/offline/types.ts | android | UI 新组件隔离，API/离线字段统一更新；原生或后台接口需先确认在途改动归属 |
| evoagent/release/manager.py、delivery.py | assets | 资产/发布线维护生产端；客户端验签由 Android 线维护，先共同锁定字节格式/密钥身份 |
| FEATURES.md、ROADMAP.md、FEATURE_SPLIT.md、IMPLEMENTATION.md、GAP_ANALYSIS.md | integration | 开发者提交证据和待更新条目，集成人更新当前状态并保留历史时间边界 |

workboard.json 的 shared_files 是可检查的明细；本页是规则说明。认领卡中的独占新模块不需要无关角色代写，但接入上表文件时要排入串行合入队列。

## 开发前的基线规则

当前基线状态为candidate，已有固定准备提交但尚未发布。候选源码摘要清单只能帮助定位在途内容，不能替代 Git 历史、依赖锁文件或一次提交快照验收。

2026-10-23用户指定当前仅codex在当前项目开发：采用单会话串行队列，同时仅开发1张卡，不另建工作树。共享文件由同一会话按卡片范围串行接线；原review的作者和独立审阅要求不变。原任务目录占用不能永久作为后续阻塞，待审接口可用于后续实现，但不能代替独立接受或发布。

集成人发布基线时逐项确认：

1. 区分既有执行安全提交、路由/回归提交、本轮运行/审批改动、独立通知改动；不使用 git add -A 混入未知文件。
2. 将运行/问答/审批源码、相关测试、schema 迁移和必要客户端实现作为可审阅的提交整理；通知模块由其实际负责人决定单独合入或保留在途。
3. 在干净工作树检查提交源码快照，重新记录测试结果。若通知改动未纳入，解释相应测试清单差异，不能照抄当前工作区 671/132。
4. 准备阶段填写 baseline.prepared_candidate 的精确 commit/tree、干净验证和排除范围；独立审阅后再填写 published_commit 与 status=published。ALN-04 已在 `72d20f0`，`23d3950` 只是初始历史锚点。
5. 各开发线从该 commit 开工或重放独立补丁；认领表记录每个分支真正使用的 base_commit。

默认不包含 .workbuddy/、本地数据库、令牌、设备私有数据、构建缓存或未归属产物。不要用强制重置/清理消除别人的工作区改动。

## 接口先行，按依赖整合

接口提案写在任务交付目录中，至少包含输入/输出、状态、幂等键、授权范围、版本引用、错误对象、故障与重启语义，以及提供方/消费方的责任。以下内容必须跨线审阅：

| 接口 | 提供/维护 | 消费方 | 必须对齐的事项 |
|---|---|---|---|
| Task/Run/Approval 与恢复 | runtime | Android、模型、资产、集成 | task_id 与 run_id 分离；父链；等待状态；未知副作用与租约失效的区别 |
| 不可变 Asset 引用与 Pack | assets | runtime、Android、进化/评测 | 以正式契约为准的 ID/version/digest、依赖和兼容；相同版本不覆盖内容 |
| 模型调用与费用证据 | models | runtime、预算/调度、评测 | 路由维度、实际提供方响应、预估与实际值、未知计费、超时/回退可追溯 |
| 事件/Manifest 与隐私 | integration 协调，models 承担证据子项 | 全部 | 统一字段/枚举、来源可信度、隐私级别、角色读取与脱敏 |
| 制品字节与信任根 | assets + android | 发布/运行 | 端侧验证真实字节；服务端 HMAC 不等于客户端公钥信任，不向客户端分发服务端签名秘密 |
| 手机动作与回执 | android + runtime | 任务/账本/诊断 | 绑定设备、任务、运行、effect 和授权；失联不能当作未执行；真实回执决定恢复 |

新接口未合入前，可以用显式 Mock/夹具开发独立模块；Mock 不能成为真实链路已完成的证据。依赖尚未验收时允许草稿，不允许跳过依赖关闭整包。

## 数据库与 API 扩展

新增表放在独占的 evoagent/core/schema/ 域模块，使用 DOMAIN/TABLES 自动发现，语句幂等。修改已有表走 migrations.py；候选工作区目前 Schema v3，后续版本由集成人统一排号，不能多人都私自追加版本 4。已发布迁移不重写。

CRUD 优先放独立域仓储；需要共享事务语义时提交原子接口提案。不能在已持有非重入数据库锁或 BEGIN 的事务中，调用会再次加锁/自行 commit 的共享方法。恢复领取、审批消费和预算预留不能由调用方的“先查再写”拼出伪原子性。

新增端点使用独立 api/*_api.py 与路由装饰器。当前新模块需要显式导入才能注册；server.py 的导入和统一鉴权由集成人登记。不要新增覆盖所有 /tasks/ 子路径的宽泛前缀处理器，也不要提前读取所有请求体破坏既有原始字节端点。

## 认领、交接和合并

同一任务卡只登记一个直接负责者；reviewer 是独立审阅职责，不以另一个 owner 代替。owner/reviewer 未定时保留 null，不编造人员或日期。认领后写实际 branch、base_commit、状态；尚未发布基线时注明base_commit只是实际接手源码锚点。换人时记录ownership_history、最后提交、未完成点与运行命令；已交付review卡不为接手后续范围而改写原作者。

单个提交只覆盖任务卡范围。共享改动单列，说明与其他任务的接口关系；有冲突时基于共同基线按行为重放，不能一律取“我方”或“对方”。

合入顺序：基线 → 契约/迁移 → 域实现 → 最小接线 → 对应端到端测试 → 台账证据。跨域按实际依赖排队，不要求所有线同时结束。共享运行/发布/鉴权改动必须由相应领域 reviewer 审阅，集成人负责最终全量回归。

开发完成、已合并、整包已验收是三个不同状态。交付只证明本卡的行为变化；正式真机、供应商、制品装载等验收没有证据时继续保留缺口。

2026-10-24本轮例外：用户明确要求“所有待审核的不管安排谁，你直接复合验收即可”，由codex-runtime统一复验04-UI、07-B、11-W、12-A、20-A。自己的修复须登记为用户授权的非独立复验（`review_authorization`与报告），不伪称第三方；默认作者不能自行充任reviewer的检查仍保留。此例外不扩展到基线发布、缺失真机证据或未交付的父包范围。
